## Рекомендации

1. **В таблице 031 у `battle-render.test.ts` не хватает четырёх кейсов взрыва корабля.**
   Кейсы «draws explosion frame 0 centered in the ship on the hit tick», «switches to frame 1
   after EXPLOSION_FRAME_TICKS», «draws frame 1 on the last explosion tick, then no ship»,
   «draws the player shot while the ship is down» (`battle-render.test.ts:262–306`) строят
   бой через `newBattle()` (`:51–53`, умолчания), зовут `battle.player.hit()` и ждут взрыв /
   `state === 'down'` (`:290`). С `START_SHIELD = 2` после `hit()` будет `invulnerable`, и
   `drawShip` нарисует корабль, а не взрыв: все четыре кейса упадут. В таблице перечислены
   только три кейса возрождения. Предложение: дописать в строку `battle-render.test.ts`:
   «кейсы взрыва и выстрела при сбитом корабле — с `shield: 0` (помощнику `newBattle`
   добавить параметр опций или завести `lostBattle()`)». И распространить «Правило разбиения
   кейсов» на `battle-render.test.ts`, а не только на `collisions`/`battle`.

2. **Строки таблицы 031 «`lives` → `shield`» при буквальной замене дают красные тесты.
   Нужно правило перевода значений.** `lives: k` по смыслу соответствует `shield: k − 1`, а
   не `shield: k`. Где это бьёт:
   - `scenes/play-scene.test.ts:34,206`: быстрый game over `{ lives: 1 }`. Если заменить на
     `shield: 1`, то `hit()` даст `invulnerable`, `over` не наступит. Нужно `shield: 0`.
   - `dev-snapshot.test.ts:65–72`: «shows a hit: one life less, the ship down», умолчания +
     `hit()` → ждёт `down`. Станет `invulnerable`, `shield = 1`. Кейс переименовать
     («удар по щиту»), либо строить с `shield: 0`. Плюс `:75` `{ lives: 1 }` → `shield: 0`,
     `:48` `toBe(3)` → `START_SHIELD`.
   - `scenes/title-scene.test.ts:118–130`: `{ lives: 1 }` / `{ lives: 5 }` → `shield: 0` /
     `MAX_SHIELD`. Комментарий в `loseGame` (`:21`, «about 420 ticks: 2 × (down 60 +
     invulnerable 120) + 60») → 2 × 120 + 60 = 300. Сам цикл (лимит 600) работает.
   - `battle.test.ts`: `lives: 1` (`:47,317,337,516,742,921`) → `shield: 0`; `lives: 2`
     (`:328`) → `shield: 1`; кейсы «на максимуме» (`:492,503,828`) → `MAX_SHIELD`, а не
     `MAX_LIVES − 1`; `{ lives: 0 }` бросает `RangeError` (`:313`): теперь `shield: 0`
     допустим, проверять `-1` и `MAX_SHIELD + 1`; «power-ups survive the loss of a ship»
     (`:866–874`, `run(DOWN_TICKS)`) → «переживают удар по щиту», без `DOWN_TICKS`; «a ship
     lost on the touching tick does not take it» (`:887–903`) — только с `shield: 0`, иначе
     корабль в `invulnerable` поймает капсулу на следующем тике.
   - **`battle.test.ts:512–535` «an extra life in down at 0 lives cancels game over»**
     проверяет поведение, которое В7 прямо отменяет. Кейс надо **перевернуть** (`shield: 0`,
     выстрел в полёте даёт 5000 → `isLost` остаётся `true`, `shield` = 0, через
     `GAME_OVER_DELAY_TICKS` — `over`), а не «починить». В таблице это лишь подразумевается
     («новые кейсы из списка выше»). Лучше назвать кейс явно.
   - `hud.test.ts:66` `lives: 5` → `shield: 5`. Здесь годится любое допустимое значение.

   Предложение: в начало раздела «Затрагиваемые тесты по задачам» одной строкой добавить
   правило: «`lives: k` → `shield: k − 1`; "на пределе" → `MAX_SHIELD`; любой кейс, где после
   `hit()` с умолчаниями ждут `down` / взрыв / game over, — по "Правилу разбиения"».
