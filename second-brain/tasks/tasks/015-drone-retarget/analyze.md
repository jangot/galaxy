# Анализ: Переприцеливание drone

## Общее описание функциональности

Сейчас `drone` берёт цель (центр корабля) один раз — в 1-м тике `descend` — и дальше летит к
этой точке, а дойдя, идёт прямо вниз. Корабль (2 px/тик) уходит из-под прицела одним
движением, и до конца пике опасности нет.

После задачи `drone` берёт цель заново раз в `DRONE_RETARGET_TICKS = 30` тиков (0,5 с) — в
тики `descend` `d = 1, 31, 61, …` — и сворачивает к новой точке со скоростью 1 px/тик, без
инерции и без зигзага (В1). В игре: дрон летит к месту, где был корабль, раз в полсекунды
«передумывает» и поворачивает к новому месту. На уровне 1 (`diveSpeed` 60, `descend` ≈ 190
тиков у ряда 1) — 6–7 прицелов за пике; на уровне 5 (`diveSpeed` 180, 3 px/тик, `descend` ≈
60 тиков) — 2–3 прицела: уход одним движением в начале больше не спасает.

Вся механика уже есть в рабочем дереве (задача 014): модель руления `steering.ts`
(`isRetargetTick` поддерживает любое `N`), `Enemy.descend` вызывает `aimFor` на каждом тике
переприцеливания. Задача сводится к **смене профиля `drone`** и тестам/документам.
Дизайн фичи 003 согласован и является рамкой (пункт 2 нарезки).

## Модели данных и состояние

Автомат `Enemy` не меняется (`formation | diving (peel → descend) | returning | exploding |
dead`). Состояние вылета (`aimX`, `steerVx`, `turnCounter`) — уже есть, сброс в `startDive`.

| Что                       | Сейчас (после 014)                                | После 015                                                         |
| ------------------------- | ------------------------------------------------- | ----------------------------------------------------------------- |
| `ENEMY_KINDS.drone.steer` | `{ retargetTicks: null, turnTicks: 0, maxVx: 1 }` | `{ retargetTicks: DRONE_RETARGET_TICKS, turnTicks: 0, maxVx: 1 }` |
| `DRONE_RETARGET_TICKS`    | нет                                               | `export const DRONE_RETARGET_TICKS = 30` в `enemy.ts` (утв. В1)   |
| `striker`, `raider`       | `{1, 0, 1}`, `{null, 0, 1}`                       | без изменений (`striker` меняет 016)                              |

Поведение `drone` в `descend` по тику `d` (всё уже реализовано в `Enemy.descend`):

- `d = 1`: `steerVx = clamp(LAST_PEEL_VX · side, ±1)`; при `turnTicks = 0` перезаписывается
  `desired` в этом же тике — на поведение не влияет.
- `d ∈ {1, 31, 61, …}`: `aimX = aimFor(targetX)`; у одиночного `drone` сдвиги 0, зажим
  центра не меняет; `targetX = null` → `aimX = null`.
- Каждый тик: `desired = desiredVx(центр, aimX, 1)` (±1 при gap ≥ 1, иначе 0) → `vx =
desired` → `x += vx`, `y += diveSpeed · dt`, зажим в экран.

Следствия (все — по дизайну, принято владельцем):

- Нет цели в 1-м тике (корабль `down`) → `drone` идёт прямо вниз до ближайшего тика
  переприцеливания; если корабль к нему возродился (`canBeTargeted` уже в `invulnerable`),
  подхватывает его (В3).
- Обратное тоже: если корабль упал посреди пике, на ближайшем переприцеливании `aimX = null`
  — `drone` перестаёт сворачивать и идёт прямо вниз (раньше доводил к старой цели). Отдельно
  в дизайне не оговорено, но прямо следует из правила 2 «Правил тика descend» (`null → null`);
  открытым вопросом не считаю.
- Стрельба (`fires()`: тики `D, D+20, …`), `returning`, взрыв, туннелирование — не затронуты:
  вертикаль та же, боковой шаг ≤ 1 px/тик.

**Перенос тестов «fixed …» на `raider` — что меняется в ожиданиях.** `raider` шире `drone`
(13 vs 11 px): после `afterPeel` `drone` стоит на `x = 128`, `raider` — на `x = 127`
(центр у обоих 133, см. комментарий `afterPeel`). Ожидаемые `x` в тестах пересчитываются на
−1 (`128 - i → 127 - i`, `118 → 117`, `127 - i → 126 - i`, `117 → 116`, `128 → 127`) — это
геометрия спрайта, а не подгонка под новое поведение; центры (`centerX`) остаются прежними.
Какие из четырёх реально ломаются на `drone` при `N = 30`:

| Тест                                                                 | Длина после 1-го тика          | На `drone` при `N = 30`            |
| -------------------------------------------------------------------- | ------------------------------ | ---------------------------------- |
| «fixed takes the target on the first descend tick and keeps it»      | 21 тик                         | проходит (в пределах `N`)          |
| «fixed reaches its target and then flies straight down»              | 20 тиков                       | проходит                           |
| «fixed with no target on the first descend tick flies straight down» | 31 тик (тик `d = 31` — прицел) | **падает** (на `i = 29` `x` = 127) |
| «fixed does not reuse the target of the previous sortie»             | 11 тиков                       | проходит                           |

Переносятся все четыре (так в описании и дизайне): смысл «один раз» теперь у `raider`.
«no target …» для `drone` заменяется тестом подхвата.

**Прочие тесты на `drone` проверены — не ломаются:** «descends straight down…», «completes a
full sortie…» (env `targetX: null` — прицел всегда `null`); «Enemy fire» (расписание не
зависит от `x`); «measures the gap from the center of its own sprite» (5 тиков, цель = центр);
`battle.test.ts` «an enemy shot puts the ship down» (`ONE_CORNER_ENEMY`, корабль стоит, цель
не меняется); «Enemy group aim» — на `raider`/`striker`; `wave.test.ts` «passes targetX» — на
`striker` (на `D` его переводит 016; при `N = 30` за 2 тика теста прицел не повторится);
`levels.test.ts` «ENEMY_KINDS steer» — профиль `{30, 0, 1}` проходит. Текущий прогон: 412
тестов зелёные.

## Тестируемость

Всё — юнит-тесты без canvas, детерминированно (тики `update(TICK_SECONDS, env)`, `targetX`
подаётся тестом, `Rng` не нужен):

- **Профили:** `ENEMY_KINDS.drone.steer` = `{ retargetTicks: DRONE_RETARGET_TICKS, turnTicks: 0,
maxVx: 1 }`, `DRONE_RETARGET_TICKS === 30`; `striker`/`raider` — прежние.
- **Цель держится `N` тиков, на `1 + N` — новая, `vx` меняет знак:** `afterPeel('drone')`,
  тик `d = 1` с целью справа (напр. 250) → `vx = +1`; тики `d = 2…N` с целью слева (напр. 0)
  → `vx` остаётся `+1` (цель не перебрана), `x` растёт на 1 за тик; тик `d = 1 + N` с целью
  0 → `vx = −1`. Ожидания строить через `DRONE_RETARGET_TICKS`, а не литерал 30.
- **Подхват после `null` в 1-м тике (В3):** тик `d = 1` — `aimAt(null)`; тики `2…N` с
  целью → `x` не меняется (`vx = 0`); тик `1 + N` с целью → `drone` пошёл к ней.
- По желанию: несколько прицелов подряд (`d = 1, 1+N, 1+2N`) и «упал посреди пике» (прицел
  `null` на `1 + N` → дальше прямо вниз). Вне требований задачи — на усмотрение плана.
- **Перенесённые «fixed …» на `raider`** — с пересчётом `x` под ширину 13.
- Механика `isRetargetTick` для произвольного `N` уже покрыта в `steering.test.ts` (014).

**Только глазами** (`?level=1`, `?level=5`): `drone` заметно меняет курс по ходу пике;
уход одним движением в начале на уровне 5 больше не гарантирует безопасность.

## Зависимости и ограничения

- Зависит от 014 (в рабочем дереве, не закоммичена, ждёт приёмки глазами —
  `014-steering-model/acceptance.md`). 015 опирается на этот код; при откате/правке 014
  по итогам приёмки 015 надо перепроверить. С 016 независима, но обе правят `enemy.test.ts`
  (блок «Enemy aim») и `game-design.md` («Пикирование») — возможен конфликт при слиянии;
  016 переносит пять механических тестов со `striker` на `drone` — их ожидания должны
  укладываться в окно `N` тиков (в дизайне учтено).
- Детерминизм и ADR 002/003 сохраняются: `vx` целый, X без `dt`, период в тиках.
- Производительность: без изменений (одна проверка остатка от деления на тик).
- Риск баланса — сложность уровня 5 растёт; принято владельцем (В1), проверяется на приёмке.
- Оценки дизайна («пике ~140 тиков», «~50 тиков, 1–2 прицела») зависят от ряда; по коду
  ряд 1 при `diveSpeed` 60 — 192 тика `descend` (тест «completes a full sortie»). На
  решение не влияет.
