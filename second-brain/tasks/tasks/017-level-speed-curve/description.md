# Задача: Плавный рост скорости по уровням

## Суть задачи

Скорость пике растёт рывком и потом стоит: `diveSpeed` по уровням 60 → 120 → 120 → 120 →
180 px/с (удвоение уже на 2-м уровне), а после 5-го уровня `levelConfig` повторяет
последнюю строку — роста нет вообще. Нужно сделать рост скорости пике ровным и продолжить
рост сложности после конца таблицы уровней (через темп атак). Решение предложено агентом
`architect` (консультация 2026-11-11) и утверждено владельцем.

## Детали и требования

- **Скорость пике** (решение владельца): `diveSpeed` по уровням 1–5 — **60 / 90 / 120 /
  150 / 180** px/с (1; 1,5; 2; 2,5; 3 px/тик), потолок 180.
  - Половинные px/тик разрешаются **только для вертикали пике** (`descend`) — новый
    **ADR 004** (`second-brain/decisions/004-half-pixel-dive.md`), расширяет ADR 002; в
    ADR 002 — ссылка «Расширено: ADR 004». X пике и покачивание — по-прежнему по ADR
    002/003.
  - Проверка `isAllowedDiveSpeed` в `levels.ts` (`perTick · 2` — целое, `perTick ≥ 1`);
    `isAllowedSpeed` для `swaySpeed` не меняется; JSDoc поля `diveSpeed` обновить.
  - Потолок 180 держат инвариант `ENEMY_SHOT_SPEED (240) > diveSpeed` и проверенная
    уходимость `striker`.
- **Рост после 5-го уровня** (решение владельца): для `N > LEVELS.length` `levelConfig`
  берёт последнюю строку и ужесточает тайминги, `k = N − 5`:
  - `diveIntervalTicks = max(30, 60 − 6·k)` (−0,1 с за уровень до 0,5 с);
  - `firstDiveDelayTicks = max(60, 90 − 6·k)`;
  - `diveSpeed`, `swaySpeed`, `maxSorties`, выстрелы — без изменений; пол достигается на
    10-м уровне. Константы вида `ESCALATION_*`; функция чистая, зависит только от `N`.
- **Покачивание строя** (решение владельца): `swaySpeed` 15/15/30/30/30 — не меняется.
- Уходимость `striker`: в `EVASION_CASES` (`src/game/test-evasion.ts`) добавить скорости 90
  и 150 со своими `turnY` — середина окна «T = 8 уходит, T = 0 таранит» (как в задаче
  016). **Если окна для 90 или 150 нет — стоп, NEEDS_INPUT, вопрос к архитектору.**
- В `it.each([60, 120])` в `enemy.test.ts` добавить 90 (дробный y).
- `enemy.ts`, `wave.ts`, `collisions.ts`, рендер — менять не должно понадобиться
  (`floor`/`overlaps` уже по `Math.floor`); поправить комментарии `battle.ts`
  («last level repeats») и `enemy-shot.ts`.
- `levels.test.ts`: правило `diveSpeed` → `isAllowedDiveSpeed`; «has the agreed rows»;
  «returns the last level past the end» и тест с подставной таблицей — под эскалацию.
- Обновить `second-brain/game-design.md` («Уровни», «Пикирование») и
  `second-brain/architecture/overview.md`.

## Критерии готовности

- Для уровней 1..20: проходят правила скоростей и таймеров, туннелирование,
  `ENEMY_SHOT_SPEED > diveSpeed`; `diveSpeed` не убывает по `N`, тайминги не растут, пол
  соблюдается.
- Окно уходимости `striker` при 90, 120, 150, 180 (тесты `EVASION_CASES`).
- ADR 004 написан, ADR 002 и `game-design.md` обновлены.
- Проходят `format:check`, `lint`, `typecheck`, `test`, `build`.
- Приёмка глазами владельцем: `?level=2` и `?level=4` — пике не дрожит заметно; рост
  скорости 1→5 ощущается ровным; `?level=6`+ — атаки чаще.
