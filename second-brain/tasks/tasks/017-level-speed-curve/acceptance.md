# Приёмка глазами: задача 017 — плавный рост скорости по уровням

Код реализован по `plan.md`, автоматические проверки зелёные (format:check, lint, typecheck,
test — 581, build). Задача остаётся в `tasks/` до приёмки владельцем.

## Что утвердить

1. **Дрожь пике на половинных px/тик (ADR 004).** На уровнях 2 (90 px/с = 1,5 px/тик) и 4
   (150 px/с = 2,5 px/тик) спрайт пикирующего врага смещается по вертикали шагами 1-2-1-2 /
   2-3-2-3 px. Если дрожь мешает — запасной вариант из `description.md`: целые
   60/60/120/120/180 (рост только темпом), ADR 004 отменяется.
2. **Ровность кривой.** Уровни 1 → 5 подряд: скорость пике растёт ровно, без рывка на 2-м.
3. **Эскалация за концом таблицы.** Уровень 6 заметно чаще вылетает, чем 5; на 10-м первый
   вылет через 1 с, интервал 0,5 с; в полёте одновременно не больше 3.
4. **Вражеские выстрелы** на уровнях 2 и 4 стартуют без визуальных артефактов (дробный `y`).

## Как проверить

`npm run dev`, открыть по очереди:

- `?level=2`, `?level=4` — п. 1 и 4;
- `?level=1` … `?level=5` — п. 2;
- `?level=6`, `?level=10` — п. 3.

## Замечание по плану

В `plan.md` (шаг 4, подставная активная таблица из одной строки 100/40) точки «N = 8 → 64/30,
N = 9 → 60/30» посчитаны с ошибкой на единицу: при `k = N − 1` значение 64 даёт N = 7, а
N = 8 уже упирается в пол 60. В тесте взяты N = 7 → 64/30 и N = 8 → 60/30; формула
и смысл проверки не менялись.
