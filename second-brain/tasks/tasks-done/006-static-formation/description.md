# Задача: Статичный строй врагов

## Суть задачи

На экране появляется строй врагов двух видов (`drone`, `striker`) — пока неподвижный. Вводятся таблица уровней, геометрия строя, сущность врага и волна, отдельный `Rng` боя.

## Детали и требования

- `enemy-art.ts`: `DRONE_SPRITE`, `STRIKER_SPRITE` — свои, оригинальные.
- `levels.ts`: `EnemyKind = 'drone' | 'striker'`, `LevelConfig { layout }`, `Slot { row, col, kind }` (поле `group` и символ `R` — в задаче 013; до неё `R` — неизвестный символ, `parseLayout` бросает), `LEVELS` с уровнем 1 (раскладка — точные строки из «Уточнений для реализации»: ширина 10), `levelConfig(n, levels?)` с проверкой «целое ≥ 1» и правилом «за концом — последний».
- `formation.ts`: геометрия (ячейка 16×12, до 11 столбцов, верх на y=32), без покачивания.
- `enemy.ts`: `ENEMY_KINDS { sprite }`, `Enemy` только в состоянии `formation`. `wave.ts` (`Wave(config, rng)`, `update(dt)`). Отрисовка врагов в `battle-render` (позиция — `Math.floor`).
- Отдельный `Rng` боя: `Battle(rng, opts?)`, seed из `rng` сцены.
- `BattleOptions.levels` (нужен `battle.test.ts`; третий аргумент `PlayScene` — в задаче 008). `src/game/test-levels.ts` с `ONE_CORNER_ENEMY` (`['D..........']`); тесты сцены пока остаются на `LEVELS` — переходят на тестовую таблицу в 008.

Точные интерфейсы, числа и порядок тика — в дизайне фичи (см. «Контекст»).

## Критерии готовности

- Тесты `levels`, `formation`, `enemy` (позиция = слот), `wave`, `battle` (волна строится из внедрённой таблицы), `battle-render`.
- Глазами: строй двух видов наверху, корабль работает как раньше.
- **Владелец утверждает спрайты `drone` и `striker`** — без этого задача не закрыта.
- Все проверки проходят: `format:check`, `lint`, `typecheck`, `test`, `build`.
- Игра остаётся рабочей; новые модули дописаны в `second-brain/architecture/overview.md`.
