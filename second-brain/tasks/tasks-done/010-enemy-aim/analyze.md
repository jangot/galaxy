# Анализ: Прицеливание врагов

Код: ветка `feature/002-enemies-and-levels`, база `20da398` + рабочее дерево задач 005–009
(не закоммичено). Базовая проверка до изменений: `npm test` — 17 файлов / 258 тестов
зелёные, `typecheck` чистый.

## Общее описание функциональности

Сейчас (009) пикирующий враг после дуги `peel` летит строго вниз — виды `drone` и
`striker` отличаются только спрайтом. Задача 010 даёт видам разное поведение в фазе
`descend` (решение владельца В4):

- `drone` (`aim: 'fixed'`) — в первом тике `descend` запоминает X центра корабля и
  смещается к этой точке; дальше игрок может уйти, дрон продолжает лететь «туда, где
  корабль был».
- `striker` (`aim: 'track'`) — каждый тик смещается к текущему X центра корабля.
  Боковая скорость `STEER_SPEED` = 1 px/тик меньше скорости корабля (2 px/тик) — от
  преследователя можно увернуться.

Над целью враг не дрожит: смещается только при расстоянии до цели ≥ 1 px. Ветка «цели
нет» (`targetX === null`) реализуется уже сейчас, но источника `null` в игре пока нет —
`Battle` всегда передаёт центр корабля; `null` при `down` появится в 011
(`canBeTargeted`). В игре ощущается так: дроны пикируют наискосок в точку, страйкеры
«ведут» корабль и заставляют уворачиваться. На уровне 1 есть оба вида (верхний ряд —
`S`, нижние — `D`), так что проверка глазами доступна сразу.

`aimOffsetX` (сдвиг цели члена группы `raider`) — **не в этой задаче** (013): `fixed`
целится ровно в центр корабля.

## Модели данных и состояние

**Вид врага (`ENEMY_KINDS`)** — добавляется поле прицеливания:

| Вид       | `sprite`         | `aim`     | Поведение в `descend`                           |
| --------- | ---------------- | --------- | ----------------------------------------------- |
| `drone`   | `DRONE_SPRITE`   | `'fixed'` | цель берётся один раз — в первом тике `descend` |
| `striker` | `STRIKER_SPRITE` | `'track'` | цель — `env.targetX` каждого тика               |

Тип `Aim = 'fixed' | 'track'`, `EnemyKindSpec { sprite, aim }` (дизайн, «Интерфейсы»).

**Окружение тика (`EnemyEnv`)** — `{ diveSpeed, targetX: number | null }`. `targetX` —
X центра корабля (`ship.x + Math.floor(SHIP_WIDTH / 2)` = `ship.x + 7`, корабль 15 px)
или `null`, когда целиться не во что.

**Новое внутреннее состояние `Enemy`:** зафиксированная цель `fixed` на текущий
`descend` (число или «нет цели»). Берётся в первом тике `descend` (тик `stateTicks ===
PEEL_TICKS + 1`); если в этот тик `targetX === null` — цели нет на **весь** `descend`
(прямо вниз, даже если цель появится позже — решение, принятое в discussion.md, п. 7).
Значение должно не «протекать» между вылетами: при следующем `startDive` старая цель не
используется (переписывается в первом тике нового `descend`). Для `track` хранить
ничего не нужно.

**Правило шага по X в `descend`** («Уточнения для реализации», «Точные правила»):

- `centerX = x + Math.floor(width / 2)` (x врага дробный — наследует дробный `slotX`
  покачивания и сдвигается целыми px; `centerX` тоже дробный);
- `aimX`: `fixed` — зафиксированная цель; `track` — `env.targetX`;
- `aimX` есть и `|aimX - centerX| >= 1` (шаг `STEER_SPEED * dt` = 1 px) →
  `x += sign(aimX - centerX) * STEER_SPEED * dt`; иначе `x` не меняется;
- цели нет (`fixed` без зафиксированной цели, `track` при `targetX === null`) → `vx = 0`.

Порядок внутри `update` в `descend`: (первый тик — взять цель `fixed`) → сдвиг по X и Y
(`vy = diveSpeed`) → зажим X в `[0, SCREEN_WIDTH - width]` → проверка ухода за низ
(`→ returning`). Стрельба (последний пункт порядка в дизайне) — задача 012.

Почему не дрожит: шаг 1 px и порог 1 px — после шага расстояние уменьшается ровно на 1
и не может сменить знак через ноль с перескоком; при остатке `< 1` враг стоит по X.

Зажим и цель не конфликтуют: центр корабля ∈ `[7, 248]`; крайние центры врага при
зажиме — `floor(w/2)` … `SCREEN_WIDTH - w + floor(w/2)` (дрон 11 px: 5 … 250, страйкер
13 px: 6 … 249) — цель всегда достижима, враг не «упирается» в край, ожидая цель за ним.

Константы — без новых: `STEER_SPEED = 60` (уже есть, в 009 используется только в
`returning`), `diveSpeed` — из уровня. Фаза `peel` и `returning` не меняются.

## Точки встраивания

- **`Enemy.updateDiving`** — ветка после `peel` (сейчас `this.y += env.diveSpeed * dt`):
  добавляется взятие цели `fixed` в первом тике `descend` и шаг по X; зажим X и переход
  в `returning` уже есть и остаются на месте (зажим сейчас общий для `peel` и `descend`).
- **`Enemy.startDive`** — место сброса цели прошлого вылета (если цель хранится не
  только как «взята в тике `PEEL_TICKS + 1`»).
- **`Wave.update(dt)` → `update(dt, targetX)`** — сейчас `env` создаётся один раз в
  конструкторе (`this.env = { diveSpeed }`, комментарий «Immutable per level»). С
  `targetX`, меняющимся каждый тик, это правило не выполняется: нужно окружение на тик
  (новый объект за тик или изменяемое приватное поле с `diveSpeed` уровня). Выбор —
  на стадии plan; производительность не критична (один объект на тик, ≤ 38 врагов).
- **`Battle.update`** — `this.currentWave.update(dt, targetX)` с `targetX = ship.x +
Math.floor(SHIP_WIDTH / 2)`. Порядок тика уже правильный: игрок двигается до волны,
  враг целится в позицию корабля этого тика. В фазе `cleared` тоже передаётся (волна
  обновляется в обеих фазах; врагов в полёте там нет).
- Ввод, сцены, HUD, рендер, `main.ts` — без изменений.

## Тестируемость

Всё поведение — чистая логика на `dt` и `env`, без `Rng` и canvas; покрывается в
`enemy.test.ts` прямой передачей `env` (критерий готовности):

- `ENEMY_KINDS.drone.aim === 'fixed'`, `ENEMY_KINDS.striker.aim === 'track'`;
- `peel` не зависит от `targetX` (цель далеко — дуга та же);
- `fixed`: цель берётся в первом тике `descend` (тик `P + 1`, `P = 14`); смена
  `targetX` после этого не меняет направление; враг доходит до цели и дальше идёт
  прямо вниз (x постоянен);
- `fixed`, в первом тике `descend` `targetX === null` → весь `descend` `x` не меняется,
  даже если со следующего тика передаётся число;
- `fixed`: цель прошлого вылета не используется в следующем (два вылета подряд с разными
  целями);
- `track`: каждый тик `x` смещается на 1 px к текущему `targetX`; смена стороны цели
  разворачивает смещение; в тиках с `null` — `vx = 0`, затем снова преследует;
- «не дрожит»: при `|aimX - centerX| < 1` (в т.ч. дробный центр, напр. разница 0,25 или
  0,75) `x` не меняется много тиков подряд; при разнице ровно 1 — один шаг и стоп;
- `vy` = `diveSpeed * dt` в каждом тике `descend` независимо от бокового шага;
- зажим X при цели у края (враг не выходит за `[0, SCREEN_WIDTH - width]`);
- `track` и `fixed` с одинаковой целью у видов с разной шириной — порог считается по
  центру своего спрайта (`Math.floor(width / 2)`: 5 для дрона, 6 для страйкера).

Тесты удобнее строить через `Formation` с покачиванием, но без `formation.update` (слот
стоит — x целый) плюс отдельный кейс с дробным `x` (прямая установка `enemy.x`, как в
существующих тестах зажима).

В `wave.test.ts` — детерминизм с передачей `targetX`; в `battle.test.ts` — опционально,
что источник цели — центр корабля.

Только глазами: `drone` летит наискосок в точку, где был корабль; `striker`
преследует, и от него можно увернуться.

## Зависимости и ограничения

- Зависит от 009 (реализовано в рабочем дереве; ждёт только приёмки дуги — на 010 не
  влияет: тесты считают `P` из `PEEL_SEGMENTS`).
- Скорости: боковой шаг — целый 1 px/тик (ADR 002); `x` в полёте дробный из-за
  покачивания (ADR 003) — правило порога это учитывает, рендер и коллизии берут
  `Math.floor`.
- `noUnusedParameters`/`noUnusedLocals`: `targetX` появляется сразу с потребителем
  (`Enemy`), `aim` — с чтением в `updateDiving`; `aimOffsetX` и `canBeTargeted` не
  добавлять (013 / 011).
- Тест полного вылета (`14 + 192 + 54`) и прочие тесты пике 009 должны идти с
  `targetX: null`, иначе изменится X в `descend` и время возврата.
- Риск: страйкер, преследующий корабль у края, и дрон, «промахнувшийся», уходят за низ
  в стороне от слота — возврат уже умеет догонять слот по X (`returning`), длина
  возврата ограничена (тест «catches up with a fast-swaying slot»).
- Производительность — несущественно (одна проверка и сдвиг на врага в `descend`).
