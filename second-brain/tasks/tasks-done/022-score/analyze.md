# Анализ: Счёт

Рамка — согласованный `second-brain/features/005-lives-score-game-over/design.md`
(раунд 3, пункт 3 нарезки, разделы «Счёт — в `Battle`», «Таблица очков (В1)», «Надбавка
за уровень (В2)», «Интерфейсы», «Тестирование»). Анализ уточняет его по реальному коду
рабочего дерева (задачи 020 и 021 реализованы, не закоммичены).

## Общее описание функциональности

Сейчас враги гибнут без последствий для счёта: панель показывает `000000` из заглушки
`PLACEHOLDER_SCORE` (`src/game/hud.ts`). Задача вводит настоящий счёт:

- За каждого сбитого врага (выстрелом игрока или тараном) в тик попадания к счёту
  прибавляются очки; панель обновляется в том же кадре (`PlayScene.render` строит
  `hudView(battle)` каждый кадр).
- Очки зависят от вида врага и от того, был ли он в строю или в полёте (`diving` или
  `returning`); таран всегда «в полёте» (таранить может только `isOut`).
- Очки растут на 10 % за каждый уровень выше первого, с округлением к ближайшему
  кратному 10 (половина вверх), без потолка. Считается в целых.
- Бонуса за уничтожение строя нет. Доп. жизни за очки — задача 023, не здесь.
- Новая игра (в т. ч. после Game Over → титул → Enter) начинается со счёта 0: `Battle`
  создаётся заново в `PlayScene`, счёт живёт в нём.

Ощущение в игре: за `drone` из строя на 1-м уровне +30, за него же в пике +60; на
`?level=5` — +40 / +80.

## Модели данных и состояние

**Таблица базовых очков (В1)** — `ENEMY_POINTS`:

| вид       | в строю | в полёте |
| --------- | ------- | -------- |
| `drone`   | 30      | 60       |
| `striker` | 40      | 80       |
| `raider`  | 50      | 100      |

**Формула (В2):** `killPoints(kill, level) = floor((base × (9 + level) + 50) / 100) × 10`,
где `base = ENEMY_POINTS[kill.kind][kill.inFlight ? 'flying' : 'formation']`.
`level` — целое ≥ 1, иначе `RangeError`. Базы кратны 10 → на уровне 1 формула даёт базу.

Контрольные значения (из `design.md`, закрепляются в `score.test.ts`):

| вид / уровень | 1        | 2        | 3        | 5        | 6        | 11        |
| ------------- | -------- | -------- | -------- | -------- | -------- | --------- |
| `drone`       | 30 / 60  | 30 / 70  | 40 / 70  | 40 / 80  | 50 / 90  | 60 / 120  |
| `striker`     | 40 / 80  | 40 / 90  | 50 / 100 | 60 / 110 | 60 / 120 | 80 / 160  |
| `raider`      | 50 / 100 | 60 / 110 | 60 / 120 | 70 / 140 | 80 / 150 | 100 / 200 |

Случай-ловушка float: `raider` в строю, уровень 14 → 120 (float дал бы 110). Половина
вверх: `drone` в строю, уровень 6 → 50. Уровень 1 целиком (8 `striker` + 20 `drone`, все
из строя) — 920.

**Событие убийства** — `Kill { kind: EnemyKind; inFlight: boolean }` (в
`collisions.ts`). `inFlight` = `enemy.isOut` до `kill()`; после `kill()` враг уже
`exploding`, `isOut === false`, восстановить нельзя (`src/game/enemy.ts:180`, `:197`).

**Состояние `Battle`:** новое приватное поле счёта (целое ≥ 0, старт 0), публичный
геттер `score`. `addScore(p)` в этой задаче — `score += p` (в 023 сюда добавится хук доп.
жизней). В интерфейсах `design.md` `addScore` не числится публичным — вызывается только
изнутри `Battle.update`; видимость (private) — на усмотрение плана.

## Точки встраивания

1. **`resolveCollisions`** (`src/game/collisions.ts:42`): собирает и возвращает
   `readonly Kill[]` в порядке событий. Два места `kill()`:
   - `hitByPlayerShot` (`:48-61`): перед `target.kill()` — записать
     `{ kind: target.kind, inFlight: target.isOut }`. Цель всегда `isAlive`, так что
     `isOut` до `kill()` различает строй и полёт.
   - `ram` (`:75-85`): перед `enemy.kill()` — `{ kind, inFlight: true }` (цикл уже
     фильтрует по `isOut`, можно и читать `enemy.isOut` — значение то же).
   - Правило 2 (вражеский выстрел) врагов не убивает — событий нет.
   - Максимум два убийства за тик (правило 1 и правило 3), порядок — 1 раньше 3.
2. **`Battle.update`** (`src/game/battle.ts:84`): сейчас
   `if (this.currentPhase === 'playing') resolveCollisions(...)`. Результат нужно
   разобрать: для каждого `kill` — `addScore(killPoints(kill, this.currentLevel))`.
   Начисление — до `updatePhase()`, т. е. уровень тот, на котором враг сбит (переход
   уровня возможен только из `cleared`, где коллизий нет — уровень в тик попадания
   стабилен). В `cleared` и `over` коллизий нет → счёт не меняется.
3. **`hudView`** (`src/game/hud.ts:94`): `score: battle.score`; удалить
   `PLACEHOLDER_SCORE` (`:21-22`) и обновить doc-комментарий функции.
4. Рендер, сцены, ввод — без изменений кода (кроме теста полного цикла).

Направление зависимостей: `score → {levels (EnemyKind — type), collisions (Kill — type)}`;
`collisions → levels (EnemyKind — type)` — новый type-импорт; `battle → score`. Циклов
нет: `collisions` не импортирует `score`/`battle`.

## Тестируемость

Вся логика детерминирована и без canvas:

- `score.ts` — чистые функции, табличные тесты (`it.each`).
- `collisions.ts` — ручная постановка позиций (`playerWithShot`, `wave([...])`,
  `enemy.startDive(diveOrder())` для пике; `returning` — как в существующем тесте `:169`).
- `battle.ts` — через `update` с `ONE_CORNER_ENEMY` / `RAM_LEVEL` и подстановкой
  координат выстрела/врага (паттерны уже есть в `battle.test.ts`); надбавка — через
  `startLevel`.
- `hud.ts` — `hudView(battle)` после убийства.
- `title-scene.test.ts` — строка в тесте полного цикла.

Только глазами (без отдельной приёмки, `acceptance.md` не нужен): счёт на панели растёт
по таблице, на `?level=5` `drone` из строя даёт 40.

## Зависимости и ограничения

- Зависит от 020 (сделана): `Battle` с фазой `over`, `player` в конструкторе. 021 сделана
  (тест полного цикла и `next.battle` есть) → строку `score === 0` добавляем здесь.
- Производительность: не более двух объектов `Kill` за тик — несущественно. Можно
  возвращать новый массив на каждый вызов; аллокация пустого массива 60 раз/с
  незначительна (при желании — общий пустой frozen-массив, на усмотрение плана).
- Счёт > 999999 — `formatScore` оставляет число целиком; ограничений не вводим (design).
- Числа — только целые; float в формуле не участвует.
- `Record<EnemyKind, KindPoints>` — typecheck гарантирует полноту таблицы при добавлении
  нового вида.
- Риск: `Kill` объявлен в `collisions.ts`, а используется в `score.ts` — только
  `import type`, цикла нет.
