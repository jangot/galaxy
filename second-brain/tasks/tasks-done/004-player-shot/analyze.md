# Анализ: Выстрел игрока

Сверено с кодом рабочего дерева: ветка `main`, `deb1a83` + незакоммиченные задачи
001–003 (`src/game/{sprite,art,ship,player}.ts`, `scenes/play-scene.ts`,
`scenes/scene-test-utils.ts` и тесты к ним; `npm test` — 8 файлов, 52 теста, зелёные).

## Общее описание функциональности

Четвёртая (последняя) задача фичи 001 «Корабль игрока». Корабль, который после задачи
003 уже ездит влево-вправо, получает выстрел: по нажатию «огня» (Space / Z) из носа
корабля вылетает белая полоска 1×4 и летит строго вверх со скоростью 240 px/с
(4 px/тик). На экране одновременно не больше одного своего выстрела. Пока он летит,
нажатия «огня» игнорируются и не запоминаются. Когда выстрел целиком уходит за верх
экрана, он исчезает, и можно стрелять снова. Удержание кнопки очередью не стреляет:
каждый выстрел требует нового нажатия (решение владельца В5).

По ощущению — классика жанра: игрок должен выбирать момент выстрела, потому что
следующий будет только примерно через 0,87 с (52 тика полёта до верха). Выстрел
после вылета не следует за кораблём: его `x` фиксирован.

Рамка — согласованный `second-brain/features/001-player-ship/design.md` (пункт 4
нарезки, разделы «Сущности и состояния» → Shot / Player, «Поток тика»,
`PlayScene.render`, «Интерфейсы», «Тестирование»). Этот анализ уточняет его по коду и
не перепроектирует. Фактический код 001–003 совпадает с интерфейсами дизайна
(сигнатуры `Ship`, `Player`, `PlayerIntent`, `readIntent`, `PlayScene`), поэтому
дизайн применяется к 004 без поправок.

## Модели данных и состояние

**Shot** (`src/game/shot.ts`, новый)

| Поле / константа | Значение                        | Примечание                                              |
| ---------------- | ------------------------------- | ------------------------------------------------------- |
| `SHOT_WIDTH`     | `1`                             | В4                                                      |
| `SHOT_HEIGHT`    | `4`                             | В4                                                      |
| `SHOT_SPEED`     | `240` px/с                      | В2; `240 * TICK_SECONDS === 4` ровно (ADR 002)          |
| `x`              | `readonly`, задаётся при вылете | не меняется в полёте                                    |
| `y`              | публичное изменяемое            | `y -= SHOT_SPEED * dt`; публичность нужна тестам границ |
| `isOffscreen`    | геттер: `y + SHOT_HEIGHT <= 0`  | выстрел целиком выше экрана                             |

Позиция — левый верхний угол прямоугольника, как у `Ship` (`src/game/ship.ts:17`).
Стиль — как у `Ship`: параметры-свойства конструктора (`constructor(public x = ...)`,
`src/game/ship.ts:22`), JSDoc на английском, константы с комментарием про px/тик
(`src/game/ship.ts:9-10`).

**Цвет** — `SHOT_COLOR = '#ffffff'` в `src/game/art.ts` (сейчас там только
`SHIP_SPRITE`, `src/game/art.ts:4`).

**Точка вылета** (`Ship.spawnShot()`, новый метод `Ship`):

- `muzzleX = x + Math.floor(SHIP_WIDTH / 2) - Math.floor(SHOT_WIDTH / 2)` = `x + 7`
  (`SHIP_WIDTH = SHIP_SPRITE.width = 15`; нос спрайта — колонка 7 строки 0, пиксель
  `Y`, `src/game/art.ts:6`; нечётная ширина и непрозрачный центр строки 0 уже
  закреплены тестом `src/game/ship.test.ts:20-23`);
- `muzzleY = y - SHOT_HEIGHT` = `208 - 4 = 204` — низ выстрела касается верха корабля
  (`Ship.y` — `readonly y = SHIP_Y`, `src/game/ship.ts:19`).

При стартовой позиции корабля `x = floor((256 - 15) / 2) = 120` выстрел вылетает в
`(127, 204)`; у краёв (`x = 0` / `x = 241`) — `muzzleX = 7` / `248`, всегда на экране.

**Player — автомат выстрела** (состояние кодируется полем `Shot | null`, наружу —
геттер `shot`):

| Состояние  | Признак         | «Огонь» (`intent.fire`)       | Переход                      |
| ---------- | --------------- | ----------------------------- | ---------------------------- |
| `Ready`    | `shot === null` | создаётся `ship.spawnShot()`  | → `InFlight`                 |
| `InFlight` | `shot !== null` | игнорируется, не буферизуется | `shot.isOffscreen` → `Ready` |

Сейчас `Player` — `readonly ship` + `update`, который только двигает корабль
(`src/game/player.ts:19-29`). Приватное поле и публичный геттер не могут называться
одинаково — поле получает другое имя (на выбор плана; в проекте прецедентов нет).

**Порядок тика `Player.update(dt, intent)`** (обязателен, закрепляется тестами):

1. `ship.update(dt, intent.move)` — движение + зажим (есть, `src/game/player.ts:27`);
2. если есть выстрел: `shot.update(dt)`; если `shot.isOffscreen` → выстрел `null`;
3. если `intent.fire` и выстрела нет → `ship.spawnShot()` (из уже сдвинутой позиции;
   в тике вылета выстрел не двигается).

**Тайминги:** выстрел, созданный в тике T с `y = 204`, после n следующих тиков имеет
`y = 204 - 4n`; при n = 51 `y = 0` (ещё на экране), при n = 52 `y = -4` →
`isOffscreen`, в том же тике удаляется. Координаты всегда целые (старт целый — `x`
корабля целый, т.к. шаг 2 px/тик и края `0`/`241` целые; шаг выстрела 4 px/тик) —
сравнения в тестах через `toBe`.

## Точки встраивания

- **Цикл обновления:** `PlayScene.update` уже вызывает
  `this.player.update(dt, readIntent(input))` (`src/game/scenes/play-scene.ts:23`).
  В 004 меняется только тело `Player.update` — к движению добавляются шаги 2–3.
  `main.ts`, `TitleScene` и `src/engine/*` не трогаются.
- **Ввод:** `PlayerIntent.fire` уже вычисляется (`src/game/player.ts:15`) и уже
  покрыт тестом edge-семантики (`src/game/player.test.ts:33-39`), но `Player` его пока
  не использует. Новых действий и привязок не нужно: `fire` → Space / KeyZ в
  `DEFAULT_BINDINGS` (`src/engine/input.ts:12-13`). Edge-семантику гарантирует
  `Input`: `press()` добавляет в `justPressed`, только если не autorepeat и клавиша
  не была зажата (`src/engine/input.ts:41-44`), `endTick()` очищает
  (`src/engine/input.ts:58-60`).
- **Отрисовка:** в `PlayScene.render` (`src/game/scenes/play-scene.ts:26-32`) слой
  выстрела — между `starfield.render` (стр. 29) и `drawSprite` корабля (стр. 31):
  `fillRect(Math.floor(shot.x), Math.floor(shot.y), SHOT_WIDTH, SHOT_HEIGHT)` цветом
  `SHOT_COLOR` (`Math.floor` — для единообразия с кораблём, стр. 31). Выстрел под
  кораблём, чтобы в тике вылета не перекрывать его. Частично ушедшего за верх
  выстрела не бывает (`y` идёт 4 → 0 → −4, а при `y = −4` он уже удалён); если бы был —
  канвас обрезал бы его сам. Комментарий класса «starfield and the player ship»
  (стр. 10) стоит дополнить выстрелом.
- **HUD:** не затрагивается.
- **Документация:** `second-brain/architecture/overview.md`, раздел «Игра».

## Тестируемость

Вся логика — без canvas (Vitest, environment `node`), детерминированно через `dt =
TICK_SECONDS`; случайности в задаче нет (`createRng(1)` в тестах сцены — только для
звёзд). Числа — через экспортируемые константы, как в существующих тестах
(`const STEP = SHIP_SPEED * TICK_SECONDS`).

- **`shot.test.ts`:** `Number.isInteger(SHOT_SPEED * TICK_SECONDS)`; один `update` —
  `y` уменьшился ровно на `SHOT_SPEED * TICK_SECONDS`, `x` прежний; граница прямой
  установкой: `new Shot(x, -SHOT_HEIGHT).isOffscreen === true`,
  `new Shot(x, -SHOT_HEIGHT + 1).isOffscreen === false`.
- **`ship.test.ts`:** `spawnShot()` у корабля в известной позиции —
  `shot.x === ship.x + Math.floor(SHIP_WIDTH / 2) - Math.floor(SHOT_WIDTH / 2)`,
  `shot.y + SHOT_HEIGHT === ship.y`.
- **`player.test.ts`** (интент — простые объекты `{ move, fire }`, как в
  существующем тесте движения, без `Input`):
  - новый `Player` — `shot === null`;
  - `fire` при отсутствии выстрела → выстрел есть, в точке вылета из уже сдвинутого
    корабля (`move: 1, fire: true` в одном тике);
  - `fire` при летящем → тот же объект (`toBe`), второго нет;
  - уход за экран прямой установкой `y = -SHOT_HEIGHT + 1` + один `update`:
    без `fire` → `shot === null`; с `fire` → новый объект в этом же тике из носа;
  - выстрел не следует за кораблём: после вылета `move: 1` несколько тиков — `shot.x`
    неизменен.
  - TS strict: геттер возвращает `Shot | null`, в тестах нужен сужающий `expect`/guard
    или `!` (правило `no-non-null-assertion` в конфиге ESLint не включено —
    `tseslint.configs.recommended`).
- **`play-scene.test.ts`** (только через `step()`, иначе `pressed()` не гасится):
  `input.press('fire')` → `step(…, 1)` → `player.shot !== null`; кнопку держать (без
  `release`): ещё `step(…, 51)` — тот же выстрел, `step(…, 1)` — `null`, дальше
  остаётся `null`; повторное нажатие (`release` + `press`) — новый выстрел.

**Только глазами (`npm run dev`):** выстрел виден как белая полоска из носа, летит
ровно без подёргивания, не перекрывает корабль в тике вылета; один выстрел за раз;
удержание не даёт очереди; после ухода за верх снова можно стрелять; выстрел из
корабля, прижатого к краю, тоже из носа.

## Зависимости и ограничения

- **Задачи 001–003 реализованы** в рабочем дереве (не закоммичены): 001 и 003 закрыты
  (`second-brain/tasks/tasks-done/`), 002 — код готов, ждёт утверждения вида корабля
  владельцем (В7). Для 004 это не блокер: `spawnShot` выводится из `SHIP_WIDTH` и
  `y`, а не из рисунка; если владелец перерисует корабль, правило «нечётная ширина,
  нос в центре строки 0» держит тест `src/game/ship.test.ts:20-23`. Меняться может
  только `art.ts`; при смене высоты спрайта `SHIP_Y = 208` и `muzzleY = y - 4` не
  зависят от высоты.
- **Правило скоростей (ADR 002):** 240 px/с даёт ровно 4 px/тик — подёргивания нет,
  координаты целые; закрепляется тестом-инвариантом.
- **Фиксированный шаг 60 тиков/с:** интервал между выстрелами (52 тика) задаётся
  только геометрией (стартовый `y` и скорость), отдельного таймера перезарядки нет.
- **Производительность:** один объект и один `fillRect` за кадр — несущественно.
- **Сцена:** переход `TitleScene → PlayScene` по `pressed('start')`
  (`src/game/scenes/title-scene.ts`); «огонь» — отдельное действие, на переход не
  влияет, на титуле не стреляет.
- **Вне рамок:** коллизии с врагами (`Player.removeShot()` — в фиче коллизий), звук
  выстрела, смерть корабля и судьба выстрела при ней.
- **Риск:** если вызвать `PlayScene.update` в тестах без `endTick()`,
  `pressed('fire')` останется истинным и тест «нет очереди» сработает не по той
  причине — поэтому тесты сцены строго через `step()` (как уже сделано в
  `play-scene.test.ts`).

отдельную задачу не нужно.
