# Задача: Покачивание строя и ADR 003

## Суть задачи

Строй начинает покачиваться влево-вправо. Для медленных скоростей вводится ADR 003: разрешены двоичные дроби px/тик, таймеры — в целых тиках.

## Детали и требования

- ADR 003 в `second-brain/decisions/`: скорости 1/2, 1/4, 1/8 px/тик (30/15/7,5 px/с) разрешены, таймеры считаются в тиках; расширяет ADR 002.
- `isAllowedSpeed`, поле `swaySpeed` в `LevelConfig` (15 px/с на старте), `Formation.update` с разворотом на размахе ±16 px.
- Валидация таблицы уровней: `swaySpeed` допустим. В тестовых таблицах `test-levels.ts` — `swaySpeed = 15`.
- Инвариант `swaySpeed < STEER_SPEED` — не здесь, а в задаче 009 (появляются `STEER_SPEED` и возврат).

Точные интерфейсы, числа и порядок тика — в дизайне фичи (см. «Контекст»).

## Критерии готовности

- `formation.test.ts`, тест валидации таблицы.
- Глазами: строй качается ровно, без подёргивания.
- Все проверки проходят: `format:check`, `lint`, `typecheck`, `test`, `build`.
- Игра остаётся рабочей; новые модули дописаны в `second-brain/architecture/overview.md`.
