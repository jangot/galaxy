# Анализ: Дуга щита над кораблём

Код: ветка `feature/008-ship-shield`, база `33e77e7` + незакоммиченная задача 031 (рабочее
дерево). Базовая проверка: `npm test` — 32 файла, 1000 тестов зелёные; `typecheck` чистый.

## Общее описание функциональности

После 031 щит существует только в логике (`Player.shield`, 0…5) и временно показан
иконками кораблей в HUD. Задача 032 делает щит видимым на поле: над кораблём —
одноцветная дуга 15×4, цвет которой отражает уровень (5 зелёный → 4 светло-зелёный →
3 жёлто-зелёный → 2 жёлтый → 1 красный; на 0 дуги нет). На старте (`START_SHIELD = 2`)
игрок видит жёлтую дугу; удар по щиту сразу перекрашивает её (с 1 — дуга исчезает), капсула
`L` и пороги очков «зеленят». Во время неуязвимости дуга мигает вместе с кораблём (в
«выключенной» фазе не видно ни корабля, ни дуги). При гибели (`down`) — только взрыв.

Это чистая отрисовка: логика, хитбокс (15×16 спрайта корабля), коллизии и снимок не
меняются. Рамка — согласованный `second-brain/features/008-ship-shield/design.md`
(разделы «Пиксель-арт и цвета», «Интерфейсы», `drawShip`, таблица тестов «032», нарезка
п. 2).

## Модели данных и состояние

Новых сущностей и состояний нет. Используются существующие:

| Что                 | Где                      | Значение / смысл                                         |
| ------------------- | ------------------------ | -------------------------------------------------------- |
| `player.shield`     | `player.ts:94` (геттер)  | 0…`MAX_SHIELD`; падает в тик удара; в `down` всегда 0    |
| `player.state`      | `player.ts`              | `active` / `invulnerable` / `down`                       |
| `player.stateTicks` | `player.ts`              | 0 в тике входа в состояние                               |
| `MAX_SHIELD = 5`    | `player.ts:19`           | длина массивов дуги = 6                                  |
| `START_SHIELD = 2`  | `player.ts:17`           | по умолчанию в каждом `newBattle()` тестов — дуга жёлтая |
| `BLINK_TICKS = 4`   | `battle-render.ts:15`    | 4 тика виден, 4 скрыт; виден в тике входа                |
| `SHIP_Y = 208`      | `ship.ts:9`              | верх корабля                                             |
| `SHIP_WIDTH = 15`   | `ship.ts:6` (из спрайта) | ширина дуги должна совпадать                             |

Новые константы данных (`art.ts`, по дизайну):

| Константа         | Тип                           | Значение                                                                           |
| ----------------- | ----------------------------- | ---------------------------------------------------------------------------------- |
| `SHIELD_COLORS`   | `readonly (string \| null)[]` | `[null, '#ff3b3b', '#ffe14f', '#c8e84a', '#8ee05a', '#4fd16a']` (индекс = уровень) |
| `SHIELD_SPRITES`  | `readonly (Sprite \| null)[]` | `[null, дуга(цвет 1), …, дуга(цвет 5)]`, 6 литеральных элементов                   |
| `SHIELD_OFFSET_Y` | `-5`                          | верх дуги относительно `ship.y`: строки 203…206, строка 207 пустая                 |

Форма дуги (палитра `{ '#': color }`, первый проход, утверждается на приёмке):

```
....#######....
..##.......##..
.#...........#.
#.............#
```

Все 4 строки по 15 символов (проверено), непрозрачных пикселей 7 + 4 + 2 + 2 = 15.
Ширина = `SHIP_WIDTH` — дуга у краёв экрана не обрезается (корабль зажат в
`0…SCREEN_WIDTH − SHIP_WIDTH`).

`SHIELD_GAUGE_EMPTY_COLOR` из блока интерфейсов дизайна — **не в этой задаче** (033).

## Точки встраивания

- **Отрисовка:** только `drawShip` в `battle-render.ts:61–71`. Сейчас: `down` → взрыв и
  `return`; `invulnerable` в нечётной фазе мигания → `return`; иначе `drawSprite(SHIP_SPRITE)`.
  Дуга добавляется в ветку «иначе» после спрайта корабля: если `SHIELD_SPRITES[shield]` не
  `null` — `drawSprite` в `(x, y + SHIELD_OFFSET_Y)` с теми же уже округлёнными `x`, `y`.
  Ранние `return` уже дают «нет дуги в `down` и в выключенной фазе мигания» без новых веток.
- **Порядок слоёв** в `drawBattle` не меняется: корабль (и дуга) — последний слой, после
  выстрелов и врагов. Дуга (203…206) с кораблём (208…223) не пересекается, поэтому порядок
  «корабль, затем дуга» на картинку не влияет, но фиксирует порядок `fillRect` в тестах —
  дизайн задаёт «спрайт корабля и, если `shield > 0`, дуга».
- **Цикл, ввод, HUD, сцены, коллизии** — не затрагиваются.
- **Импорты:** `art.ts` остаётся с единственным импортом `./sprite` (правило дизайна; иначе
  цикл `art → player → ship → art` и TDZ на `SHIP_SPRITE`). `battle-render.ts` берёт
  `SHIELD_SPRITES`, `SHIELD_OFFSET_Y` из `./art`; `MAX_SHIELD` ему не нужен (индексирует
  массив по `player.shield`).

## Тестируемость

**Unit (детерминированно, без canvas — через `recorder()`):**

- `art.test.ts` — инварианты данных из таблицы выше. Он может импортировать `MAX_SHIELD`
  (`player.ts`) и `SHIP_WIDTH` (`ship.ts`): тест — не часть графа модулей приложения, цикла
  нет (так и задумано дизайном).
- `battle-render.test.ts` — кейсы, где сравнивается полный список `fillRect` с кораблём и
  которые поэтому сломаются, как только дуга появится (по умолчанию щит 2 — дуга в каждом
  кадре). Все используют `shipCalls`, так что достаточно обновить помощник и передать
  уровень там, где он не стартовый:
  - `drawBattle`: «draws the enemies, then the ship…», «draws the shot first…», «with
    doubleShot…», «moves the ship calls…», «floors fractional coordinates» (дуга от
    `floor(10.5) = 10`), «floors fractional enemy coordinates»;
  - «draws every enemy of the default wave» — считает **число** вызовов:
    `enemyPixels + opaquePixels(SHIP_SPRITE)` → добавить пиксели дуги уровня `START_SHIELD`;
  - `drawBattle explosions` — 4 кейса (корабль `active`, щит 2);
  - `drawBattle ship states`: «blinks the ship where it was hit» и «draws the ship again
    once active» — после `hit()` щит **1** (красная дуга), помощнику нужен уровень 1;
    кейсы взрыва с `shield: 0` уже не содержат корабля — не меняются, но становятся
    проверкой «нет дуги в `down`»;
  - `drawBattle enemy shots` — 4 кейса с `shipCalls`; `drawBattle asteroid` — 4 кейса;
    «draws nothing extra before the asteroid spawns» сравнивает два `draw` — не меняется.
- Новые кейсы `battle-render.test.ts`:
  - дуга рисуется **после** корабля в `(ship.x, SHIP_Y + SHIELD_OFFSET_Y)` цветом
    `SHIELD_COLORS[k]` для каждого `k = 1…MAX_SHIELD` (`newBattle({ shield: k })`);
  - `shield: 0`, корабль `active` — только спрайт корабля, без дуги;
  - `down` (`shield: 0`, `hit()`) — нет дуги (покрыто существующими кейсами взрыва; можно
    явно);
  - выключенная фаза мигания — ни корабля, ни дуги (существующий «blinks…» после
    `run(BLINK_TICKS)` ожидает `enemyCalls` — это и есть проверка);
  - удар по щиту перекрашивает дугу в тот же тик (`shield: 3` → `hit()` → дуга цвета 2).

**Только глазами (`acceptance.md`, владелец / `/qa`):**

- форма и отступ дуги, её читаемость на звёздном фоне;
- пять цветов и различимость уровней 3 (`#c8e84a`) и 4 (`#8ee05a`) — удобно сравнить
  стартом с `?shield=3` и `?shield=4` (параметр из 031, `dev-params.ts`);
- смена цвета по ударам (2 → 1 → нет дуги) и по капсуле `L` (2 → 3);
- мигание дуги синхронно с кораблём;
- «удар в щит» — вражеский выстрел гаснет примерно у дуги;
- свой выстрел у дуги (см. «Открытые вопросы», п. 1 — уточнение геометрии).

## Зависимости и ограничения

- Зависит от 031 — сделано в рабочем дереве: `Player.shield`, `BattleOptions.shield`,
  `?shield=N` есть; `newBattle({ shield: 0 })` уже используется в `battle-render.test.ts`.
- **Цикл импортов** — главный риск: `art.ts` не должен импортировать `player.ts`/`ship.ts`
  (через `ship.ts` → `art.ts` получится TDZ на `SHIP_SPRITE` при загрузке). Поэтому массивы —
  литералы из 6 элементов, а связь с `MAX_SHIELD`/`SHIP_WIDTH` держит `art.test.ts`.
- Производительность: +15 `fillRect` за кадр — пренебрежимо (волна — сотни пикселей).
- `drawSprite` ставит `fillStyle` только при смене цвета; рекордер фиксирует `fillStyle` на
  каждом вызове, так что ожидания из `spriteCalls` совпадут.
- Разрешение: дуга 203…206 по Y целиком в экране, по X — в границах корабля.
- Хитбокс не меняется — дуга только картинка (решение дизайна, «Альтернативы»).
- Задача 033 зависит от `SHIELD_COLORS` отсюда.

## Открытые вопросы

Вопросов, блокирующих план, нет; вкусовое — на приёмку (форма дуги, оттенки 3 и 4, выстрел
у дуги). Замечания к дизайну по коду:

1. **«Свой выстрел наполовину скрыт дугой» — по коду не так.** `Player.update` двигает
   выстрелы, затем создаёт новый (`player.ts:172–178`), `spawnShot` ставит его в
   `x = ship.x + 7`, `y = 204…207` (`SHOT_HEIGHT = 4`, `SHOT_WIDTH = 1`). У дуги в колонке 7
   непрозрачна только верхняя строка (`y = 203`); строки 204…206 в колонке 7 пусты. Значит, в
   тик выстрела он виден **целиком, внутри дуги под её верхней перекладиной**; в следующий
   тик (обычная скорость 4 px/тик → `y = 200…203`) его нижний пиксель на 1 тик закрыт
   перекладиной (дуга рисуется после выстрелов); быстрый выстрел (6 px/тик → `198…201`) не
   перекрывается вовсе. Логики это не меняет; в `acceptance.md` формулировать по факту
   («выстрел появляется внутри дуги и проходит сквозь её верх»). Запасной вариант дизайна —
   разрыв перекладины над носом — остаётся на решение владельца после приёмки.
2. **Порядок «корабль, затем дуга».** Не влияет на картинку (не пересекаются), фиксируется
   ради тестов — следовать дизайну.
3. **Комментарий `SHIP_Y` в `ship.ts:8`** и описание в `overview.md` устаревают с этой
   задачей — включены в объём как правка комментария/документа (в нарезке дизайна для 032
   не названы явно, но иначе база знаний разойдётся с кодом).
