# Анализ: Верхняя панель (HUD)

Рамка — согласованный `second-brain/features/004-hud/design.md` (раунд 2, пункт 2 нарезки).
Анализ уточняет его по реальному коду, включая шрифт из задачи 018 (в рабочем дереве,
не закоммичен).

## Общее описание функциональности

Во время игры в верхней полосе экрана (y = 0…23, над строем) рисуется панель из трёх
секций:

- слева — подпись `SCORE` (красная) и под ней `000000` (белая, 6 цифр с ведущими нулями);
- по центру — подпись `LEVEL` и под ней номер текущего уровня, выровненный по левому краю
  подписи;
- справа — иконки жизней (уменьшенный силуэт корабля) в строке значений, от правого края
  влево; показывается общее число жизней, включая корабль на поле (заглушка 3).

Меняется только номер уровня — в тик появления новой волны (панель читает `battle.level`,
своего состояния нет). Счёт и жизни — заглушки до будущих фич очков и жизней. Панель
рисуется последней, поверх боя, без фона: звёзды видны под ней, враг, возвращающийся в
строй сверху, и выстрел игрока проходят «под» текстом. Поле не сдвигается.

Расширяемость: каждая секция — поле в `HudView`, прямоугольная зона `HudZone` и своя
функция отрисовки; будущая секция улучшений добавляется так же, тест непересечения зон
сразу её проверит.

## Модели данных и состояние

Конечных автоматов, таймеров и случайности нет: панель — чистая функция от `Battle`.

**`HudView`** (`hud.ts`): `level` ← `battle.level`; `score` ← `PLACEHOLDER_SCORE = 0`;
`lives` ← `PLACEHOLDER_LIVES = 3` (общее число, включая текущий корабль).

**Шрифт (реальный код 018, `src/game/font.ts`):** `GLYPH_WIDTH = 7`, `GLYPH_HEIGHT = 7`,
`CHAR_ADVANCE = 8`; набор — 37 глифов (`0–9`, `A–Z`, пробел); `textWidth(t) = t.length * 8`
(хвостовой зазор включён); `drawText(ctx, text, x, y, color)` — один `fillStyle` на вызов,
`fillRect(…, 1, 1)` на пиксель маски, бросает на символе без глифа до отрисовки. Глиф
рисуется в клетке `x…x+6`, `y…y+6`. У `L` и `1` первая колонка пустая (чернила с col 1) —
`LEVEL` визуально начинается на 1 px правее `zone.x`; на раскладку не влияет.

**Константы раскладки (`hud.ts`)** — проверены на реальных размерах шрифта:

| Константа          | Значение                                  | Проверка                                                                               |
| ------------------ | ----------------------------------------- | -------------------------------------------------------------------------------------- |
| `SCORE_DIGITS`     | `6`                                       | `formatScore(0) = '000000'`                                                            |
| `SCORE_LABEL`      | `'SCORE'`                                 | `textWidth = 40`                                                                       |
| `LEVEL_LABEL`      | `'LEVEL'`                                 | `textWidth = 40`                                                                       |
| `HUD_HEIGHT`       | `24`                                      | y = 0…23; запас до верха строя/дуги/взрыва (см. ниже)                                  |
| `HUD_MARGIN_X`     | `8`                                       | одна клетка                                                                            |
| `HUD_LABEL_Y`      | `4`                                       | подписи y = 4…10                                                                       |
| `HUD_VALUE_Y`      | `14`                                      | значения y = 14…20, иконки y = 14…21 (при высоте 8); зазор между строками 3 px         |
| `SCORE_ZONE`       | `{ x: 8, y: 4, width: 48, height: 17 }`   | `width = SCORE_DIGITS * CHAR_ADVANCE = 48` ≥ `textWidth('SCORE') = 40`; x = 8…55       |
| `LEVEL_ZONE`       | `{ x: 108, y: 4, width: 40, height: 17 }` | `width = textWidth(LEVEL_LABEL) = 40`, `x = (256 − 40) / 2 = 108`; x = 108…147; 5 цифр |
| `LIFE_ICON_STEP`   | `10`                                      | иконка ≤ 8 + зазор 2                                                                   |
| `LIVES_ICON_SLOTS` | `5`                                       | резерв раскладки                                                                       |
| `LIVES_ZONE`       | `{ x: 200, y: 14, width: 48, height: 8 }` | `width = 4 * 10 + 8 = 48`, `x = 256 − 8 − 48 = 200`; x = 200…247, y = 14…21            |

Высота текстовых зон `HUD_VALUE_Y + GLYPH_HEIGHT − HUD_LABEL_Y = 14 + 7 − 4 = 17` (y = 4…20).
Все зоны лежат в `0…256 × 0…24` (низ: 21 и 22 ≤ 24) и попарно не пересекаются
(x: 8…56, 108…148, 200…248). Свободно под будущие секции: x = 56…107 и 148…199 в обеих
строках, строка подписей над жизнями (x = 200…247, y = 4…10).

**Иконки жизней:** иконка `i` (0 — самая правая) на
`x = LIVES_ZONE.x + LIVES_ZONE.width − LIFE_ICON_SPRITE.width − i * LIFE_ICON_STEP`,
`y = HUD_VALUE_Y`. При ширине 8: 3 иконки — x = 240, 230, 220; 5-я — x = 200 (ровно левый
край зоны). Правый край самой правой иконки всегда 248 при любой ширине ≤ 8. Число `8` в
ширине зоны — это предел размера иконки, а не `LIFE_ICON_SPRITE.width` (см. «Открытые
вопросы», п. 2).

**`art.ts`:** `LIFE_ICON_SPRITE` (≤ 8×8, уменьшенный силуэт корабля 15×16; рисунок
утверждает владелец на приёмке), `HUD_LABEL_COLOR = '#ff5a3c'` (совпадает с цветом `R` в
палитре корабля), `HUD_VALUE_COLOR = '#ffffff'`.

**Запас по высоте (проверено по коду):** верх спрайта верхнего ряда строя — 33 (striker,
raider 13×9) и 34 (drone 11×8) при `FORMATION_TOP = 32`, `CELL_HEIGHT = 12`. Апекс дуги
вылета (`PEEL_SEGMENTS[0]`: 4 тика `vy = −1`) — 29/30. Кадры взрыва — 11×9 и 13×9,
центрируются через `Math.floor((h − 9) / 2)`: для drone смещение −1, верх взрыва на апексе
= 29. Дизайн указывает 28 — это консервативная оценка (реальный минимум 29), на решение не
влияет: `HUD_HEIGHT = 24` с запасом ≥ 4 px, тестовый предел `HUD_HEIGHT ≤ 28` корректен.

## Точки встраивания

- **Отрисовка:** `PlayScene.render` (`src/game/scenes/play-scene.ts:33-38`) — после
  `drawBattle(ctx, this.battle)` добавить `drawHud(ctx, hudView(this.battle))`. Порядок
  внутри панели: счёт → уровень → жизни.
- **Цикл обновления:** не меняется (`update` сцены и `Battle` не трогаются).
- **Ввод:** не затрагивается.
- **Данные:** `hudView` читает только `battle.level`; новых полей в `Battle` нет.
- **`?level=N`:** `main.ts` → `TitleScene(rng, startLevel)` → `PlayScene(…, { startLevel })`
  → `Battle` — панель показывает N с первого кадра без доработок.
- **`TitleScene`:** не меняется.

## Тестируемость

Всё, кроме вида, покрывается без canvas.

**`hud.test.ts`:**

- `formatScore(0) === '000000'`, `formatScore(1234567) === '1234567'` (без обрезки);
  `formatLevel(12) === '12'`.
- `hudView(new Battle(createRng(1), { levels: TWO_LEVELS, startLevel }))` для 1 и 3:
  `level === startLevel`, `score === PLACEHOLDER_SCORE`, `lives === PLACEHOLDER_LIVES`.
  `startLevel: 3` за концом `TWO_LEVELS` допустим (эскалация `levelConfig`, как
  `startLevel: 5` в `battle.test.ts`). Тайминг смены уровня — не дублировать.
- Зоны `HUD_ZONES` попарно не пересекаются; каждая в `0…SCREEN_WIDTH × 0…HUD_HEIGHT`;
  `HUD_HEIGHT ≤ 28` (комментарий про верх взрыва на апексе вылета).
- Вместимость через `textWidth` / `CHAR_ADVANCE` / `LIFE_ICON_STEP`: `SCORE_ZONE` — подпись
  и `SCORE_DIGITS` цифр; `LEVEL_ZONE` — подпись; `LIVES_ZONE` — `LIVES_ICON_SLOTS` иконок.
- `LIFE_ICON_SPRITE` ≤ 8×8 и ширина ≤ `LIFE_ICON_STEP`; высота укладывается в
  `LIVES_ZONE.height`.

**`hud-render.test.ts`** (через `recorder()`):

- Все `fillRect` — в `0…SCREEN_WIDTH` по x и `y + h ≤ HUD_HEIGHT`.
- Изоляция секций: пары видов, отличающиеся одним полем (`level` 1/2, `score` 0/123,
  `lives` 3/2) — различающиеся вызовы лежат в зоне этой секции, остальные совпадают.
  Сравнивать удобно как множества/мультимножества вызовов, а не по индексам (при разной
  длине текста индексы сдвигаются).
- Позиции: вывод `drawHud` содержит ровно вызовы эталонных `drawText(LABEL, zone.x,
HUD_LABEL_Y, HUD_LABEL_COLOR)` и `drawText(value, zone.x, HUD_VALUE_Y, HUD_VALUE_COLOR)`
  (эталон — отдельный `recorder()`); для `level` 9 и 10 первая цифра в `LEVEL_ZONE.x`.
- Число иконок = `lives` (через число копий пикселей `LIFE_ICON_SPRITE`); правый край
  самой правой — `LIVES_ZONE.x + LIVES_ZONE.width`.
- Цвета подписей и значений. Иконка рисуется цветами своей палитры (`drawSprite`), не
  цветами HUD — тест цветов это учитывает.

**Только глазами** (`acceptance.md`): читаемость шрифта при ×2…×4, рисунок иконки, цвета,
положение относительно строя (покачивание ±16 px, верхний ряд `raider` на уровнях 4–5,
взрыв на апексе вылета не налезает), враг, возвращающийся через панель, и выстрел под
текстом, смена номера после паузы, `?level=9` → 10 без сдвига первой цифры.

## Зависимости и ограничения

- Зависит от 018 (шрифт) — код в рабочем дереве, не закоммичен; 019 опирается на него.
- Целые координаты на входе `drawText`/`drawSprite` — все координаты панели — целые
  константы, `Math.floor` не нужен.
- Производительность: ≈ 30 пикселей на глиф × ~23 символа + 3 иконки ≈ 600–700 `fillRect`
  на кадр поверх боя — приемлемо при 60 FPS (дизайн: кэш не нужен).
- Граф импортов без циклов: `hud → {config, font}` (+ `import type { Battle }`),
  `hud-render → {hud, font, art, sprite}`, `play-scene → {hud, hud-render}`. `engine` не
  затрагивается.
- `import type` для `Battle`, `HudView`, `HudZone`, `Sprite`.
- Риск: при `lives > LIVES_ICON_SLOTS` или счёте длиннее 6 цифр вывод выйдет за зону —
  сейчас невозможно (константы); правило решат будущие фичи (дизайн, «Крайние случаи»).

## Открытые вопросы

Вопросов к владельцу нет: В1–В7 закрыты, рисунок иконки утверждается на приёмке. Мелкие
уточнения дизайна по коду (решаются на стадии plan, не блокируют):

1. В дизайне ссылка `overview.md:49` устарела — после записи о шрифте (018) строка про
   «нижние 16 px» — `overview.md:59`.
2. Ширина `LIVES_ZONE` по формуле `(SLOTS − 1) * STEP + 8`: число `8` — предел размера
   иконки, а не `LIFE_ICON_SPRITE.width`. Предлагается именованная константа (напр.
   `LIFE_ICON_MAX_SIZE = 8` в `hud.ts`), на ней же — тест «иконка ≤ 8×8». Тогда зона не
   зависит от рисунка иконки, а `hud.ts` не импортирует `art.ts`.
3. Верх взрыва на апексе вылета по коду — y = 29 (дизайн: 28). Тестовый предел
   `HUD_HEIGHT ≤ 28` оставить как в дизайне (консервативно) — комментарий в тесте должен
   быть точным («≤ 28: на 1 px выше самого высокого взрыва» либо просто «свободная полоса
   0…28»).
