# Анализ: Несколько выстрелов и скорость пули

Код: ветка `feature/006-asteroid-bonuses`, коммит `b9f6535`. Рамка — согласованный
`second-brain/features/006-asteroid-bonuses/design.md` (раунд 3, пункт 1 нарезки).
Анализ уточняет его по коду и не перепроектирует.

## Общее описание функциональности

Задача готовит корабль игрока к двум улучшениям пули, которые появятся позже
(фича 006): **быстрой пуле** и **двум пулям**. Сейчас у `Player` ровно один выстрел
(`activeShot: Shot | null`), а скорость выстрела — константа модуля `shot.ts`.
После задачи:

- у `Player` будет **список** выстрелов в полёте `shots` длиной `0…maxShots`;
- у каждого `Shot` — своя скорость `speed` (по умолчанию `SHOT_SPEED = 240`, быстрая —
  `FAST_SHOT_SPEED = 360`);
- у `Player` появятся улучшения `powerUps` и метод `grantPowerUp(kind)`;
- правило 1 коллизий и `drawBattle` будут работать со всеми выстрелами.

Взять улучшения в игре пока негде (капсул нет до задачи 027), поэтому **в браузере
ничего не меняется**: один выстрел, 4 px/тик, огонь только при пустом списке. Новое
поведение проверяется только тестами (через прямой вызов `grantPowerUp`).

Решения владельца (В6, В7): быстрая пуля 360 px/с (6 px/тик); скорость не
складывается; «две пули» — до двух своих выстрелов на экране, огонь по нажатию, без
автоогня и буфера; улучшения держатся до конца игры (`hit()` их не снимает).

## Модели данных и состояние

### `bonus.ts` (новый, без импортов)

| Имя            | Вид                    | Значение                                                                                            |
| -------------- | ---------------------- | --------------------------------------------------------------------------------------------------- |
| `PowerUpKind`  | тип                    | `'fastShot' \| 'doubleShot'`                                                                        |
| `BonusKind`    | тип                    | `'life' \| PowerUpKind`                                                                             |
| `BONUS_KINDS`  | `readonly BonusKind[]` | `['life', 'fastShot', 'doubleShot']` — фиксированный порядок для `rng` (используется с задачи 025+) |
| `PowerUps`     | интерфейс              | `{ readonly fastShot: boolean; readonly doubleShot: boolean }` — снимок «что включено», не уровни   |
| `NO_POWER_UPS` | `PowerUps`             | оба `false`                                                                                         |

В этой задаче `BonusKind` / `BONUS_KINDS` никем не используются, кроме тестов
`bonus.ts` (если план решит их писать); заводятся по дизайну, чтобы задача 025
зависела только от готовых типов.

### `Shot`

| Поле / константа  | Сейчас                          | После                                                                     |
| ----------------- | ------------------------------- | ------------------------------------------------------------------------- |
| `x`, `y`          | `readonly x`, `public y`        | без изменений                                                             |
| `speed`           | нет (используется `SHOT_SPEED`) | `readonly speed`, третий параметр конструктора, по умолчанию `SHOT_SPEED` |
| `SHOT_SPEED`      | 240 px/с, 4 px/тик              | без изменений                                                             |
| `FAST_SHOT_SPEED` | нет                             | 360 px/с, 6 px/тик (ADR 002 — целое число px/тик)                         |
| `update(dt)`      | `y -= SHOT_SPEED * dt`          | `y -= this.speed * dt`                                                    |

Параметр по умолчанию сохраняет все вызовы `new Shot(x, y)` в `shot.test.ts`,
`ship.test.ts` и др. без правок.

### `Ship.spawnShot(speed?)`

Прокидывает скорость в `Shot`; без аргумента — `SHOT_SPEED` (существующие тесты
`ship.test.ts` не меняются).

### `Player`

Автомат корабля (`active → down → invulnerable → active`, `isLost`) **не меняется**.
Меняется автомат выстрела: вместо Ready/InFlight — список.

| Член                 | Поведение                                                                                                                                                                                                                                                             |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `shots` (геттер)     | `readonly Shot[]`, старший первым; длина `<= maxShots`. Заменяет `shot` (геттер `shot` удаляется, без совместимости)                                                                                                                                                  |
| `maxShots` (геттер)  | `powerUps.doubleShot ? 2 : 1`                                                                                                                                                                                                                                         |
| `powerUps` (геттер)  | текущий `PowerUps`; старт — `NO_POWER_UPS`                                                                                                                                                                                                                            |
| `grantPowerUp(kind)` | в любом состоянии корабля (в т.ч. `down`) включает улучшение; `true` — было выключено, `false` — повтор (no-op)                                                                                                                                                       |
| `removeShot(shot)`   | снимает конкретный выстрел; неизвестный игнорируется. **Массив заменяется (`filter`), не мутируется**                                                                                                                                                                 |
| `update(dt, intent)` | порядок прежний: таймер состояния → движение (если управляем) → полёт всех выстрелов и удаление ушедших за верх (тоже заменой массива) → огонь, если `controllable && intent.fire && shots.length < maxShots`, со скоростью `fastShot ? FAST_SHOT_SPEED : SHOT_SPEED` |
| `hit()`              | улучшения не трогает; выстрелы в полёте не снимает (как сейчас)                                                                                                                                                                                                       |

Следствия, которые нужно сохранить и закрепить тестами:

- Без улучшений поведение побитово то же: огонь при пустом списке, слот,
  освобождённый уходом за верх, свободен в том же тике; выстрел, снятый коллизией,
  освобождает слот со следующего `update` (коллизии идут после `player.update`).
- Уже летящие выстрелы сохраняют свою скорость после включения `fastShot`.
- В `down` летят все выстрелы, новых нет.
- Контракт «массив заменяется» — ради безопасного цикла по ранее полученному
  `player.shots` в правиле 1 (и позже в бонусных коллизиях задачи 026): снятие
  выстрела внутри цикла не пропускает следующий.
- Рекомендуемая деталь: `grantPowerUp` тоже заменяет объект `powerUps`
  (`{ ...powerUps, [kind]: true }`), а не мутирует — внешний код (HUD в задаче 028)
  получает неизменяемый снимок. В дизайне не оговорено, на поведение не влияет.

## Точки встраивания

- **Цикл обновления:** `Battle.update` → `player.update(dt, intent)` (лимит и скорость
  читаются внутри `Player` из `powerUps`, в `update` ничего не прокидывается) →
  `wave.update` → `resolveCollisions(player, wave)` (только `playing`). Порядок не
  меняется, `battle.ts` не правится.
- **Коллизии:** `hitByPlayerShot` (`collisions.ts:59–74`) сейчас берёт
  `const { shot } = player` и вызывает `player.removeShot()` без аргумента. Станет
  циклом по `player.shots` в порядке массива: для каждого выстрела — тот же выбор
  самого нижнего живого врага (строгий `>`, ничья — меньший индекс), `kill()`,
  `removeShot(shot)`. Убитый первым выстрелом враг уже `exploding` (`isAlive === false`)
  и для второго не существует — второй летит дальше. Итого до двух `Kill` от правила 1
  - один от тарана = до трёх за тик.
- **Отрисовка:** `drawBattle` (`battle-render.ts:22–39`) — слой «выстрел игрока»
  становится циклом по `battle.player.shots` в порядке массива; место слоя прежнее
  (после вражеских выстрелов, до врагов). Задний слой астероида/капсулы — не в этой
  задаче.
- **Ввод, HUD, сцены:** без изменений.

## Тестируемость

Вся логика задачи детерминирована и без canvas; `Rng` не участвует.

- **`shot.test.ts`:** умолчание `speed === SHOT_SPEED`; `new Shot(x, y, FAST_SHOT_SPEED)`
  за тик уходит на 6 px; оба шага — целые (ADR 002). **Инвариант пробоя врагов** для
  `levelConfig(1..20)`: `FAST_SHOT_SPEED·TICK + maxDown < SHOT_HEIGHT + minEnemyHeight`,
  `minEnemyHeight` — минимум по `ENEMY_KINDS`, `diveSpeed` — через `Math.ceil` (дробные
  2,5 px/тик с округлением в `overlaps` дают сдвиг до 3 px). Уточнение по коду: такой же
  инвариант для обычной пули уже есть в `levels.test.ts:232–244`, и там `maxDown` —
  максимум из `diveSpeed·TICK`, `PEEL_SEGMENTS[].vy` и `RETURN_SPEED·TICK`. Разумно взять
  то же выражение (с `Math.ceil`), чтобы два инварианта не расходились; при текущих
  числах результат тот же (6 + 3 = 9 < 12), рамку дизайна не меняет.
- **`player.test.ts`:**
  - без улучшений `maxShots === 1`, второй выстрел не вылетает, пока летит первый
    (существующие тесты после перевода);
  - `grantPowerUp('doubleShot')` → `true`, `maxShots === 2`; два нажатия подряд — два
    выстрела, третье игнорируется; порядок `shots` — старший первым;
  - слот, освобождённый уходом за верх, свободен в том же тике (и при двух выстрелах);
  - `grantPowerUp('fastShot')` → новый выстрел 6 px/тик, уже летящий — 4 px/тик;
  - повторный `grantPowerUp` → `false`, `powerUps` не меняется;
  - `grantPowerUp` в `down` тоже включает;
  - `hit()` улучшения не сбрасывает; после возрождения лимит и скорость прежние;
  - `removeShot(shot)` снимает именно его (второй остаётся); неизвестный — no-op;
  - массив, полученный до `removeShot`/`update`, не изменился (контракт замены).
- **`collisions.test.ts`:** два выстрела, каждый над своим врагом — **оба врага убиты в
  одном тике**, оба выстрела сняты (ловит пропуск при удалении в цикле); два выстрела
  в одного врага — убит один, второй выстрел остаётся в `shots`; порядок `Kill` — по
  порядку выстрелов; до трёх `Kill` за тик (два выстрела + таран).
- **`battle-render.test.ts`:** при двух выстрелах — два `fillRect` цвета `SHOT_COLOR` в
  порядке `shots`, после вражеских выстрелов и до врагов.
- **`ship.test.ts`:** `spawnShot(speed)` передаёт скорость.
- **Помощник `onlyShot`:** бросает при двух и более — заодно проверяет инвариант «без
  улучшений ≤ 1 выстрела» во всех переведённых тестах.

Визуально проверять нечего: игра внешне не меняется. Приёмка глазами — только
«стреляет как раньше» (один выстрел, прежняя скорость).

## Зависимости и ограничения

- Зависимостей от других задач нет; задачи 025–028 зависят от этой (`bonus.ts`,
  `Player.shots`, `powerUps`).
- ADR 002: обе скорости — целые px/тик (4 и 6). Пробоя врагов нет при текущих
  `diveSpeed ≤ 180` и `drone` высотой 8 — закрепляется тестом от констант.
- Производительность — не вопрос: не больше двух выстрелов игрока.
- Риск 1 — **пропуск второго выстрела** при удалении внутри цикла: закрыт контрактом
  «массив заменяется» и тестом «оба в одном тике».
- Риск 2 — **дрейф поведения без улучшений**: закрыт тем, что существующие тесты
  переводятся механически (`shot` → `onlyShot(player)` / `shots[0]`), а не
  переписываются по смыслу.
- `test-shots.ts` лежит в `src/game/`, попадает в `typecheck` и `lint`, но не в сборку
  (продуктовый код его не импортирует) — как `test-levels.ts`, `test-evasion.ts`.
- Документы `architecture/overview.md` (описание `Player`/`Shot`: «единственный
  выстрел», `get shot()`) и `game-design.md` («не больше одного своего выстрела»)
  по нарезке дизайна обновляются в задаче 027 (капсулы и бонусы) — здесь не трогаются.
  Между задачами `overview.md` описывает устаревший `get shot()`; это осознанное
  решение дизайна.
- Запись фичи в `second-brain/features/` в этой задаче не меняется.

## Открытые вопросы

Нет. Все числа и поведение решены владельцем (В6, В7) и дизайном. Уточнения по коду,
не меняющие рамку дизайна:

- Инвариант пробоя быстрой пулей — тем же выражением `maxDown`, что и существующий в
  `levels.test.ts` (с `Math.ceil`), см. «Тестируемость».
- `grantPowerUp` заменяет объект `powerUps`, а не мутирует его (по аналогии с
  контрактом `shots`).
