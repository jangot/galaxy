Код: ветка `feature/008-ship-shield`, база `33e77e7` (в `src/` изменений нет). Рамка —

## Общее описание функциональности

Запас кораблей (фича 005: старт 3, предел 5, гибель → 1 с пусто → возрождение в центре →
2 с мигания) заменяется **одним кораблём со щитом** — целым уровнем `0…5`:

- удар (вражеский выстрел или таран) по кораблю со щитом — `shield − 1` в тик попадания,
  корабль **остаётся на месте**, управляем, стреляет, 2 с мигает и неуязвим
  (`invulnerable`, `INVULNERABLE_TICKS = 120`); в том числе удар при `shield = 1` → `0` и
  `invulnerable`;
- удар при `shield = 0` — `down` (взрыв), это **конечное** состояние: возрождения нет,
  через 1 с (`GAME_OVER_DELAY_TICKS = 60`) бой уходит в `over`;
- рост щита: капсула `L` (+1; на максимуме — 500 очков) и пороги 5000/15000/25000/… (+1,
  сверх максимума пропадает); в `down` щит не растёт — порог, пересечённый долетевшим после
  гибели выстрелом, игру не спасает (В7);
- старт — `START_SHIELD = 2` (третий удар — game over, как прежние 3 жизни), максимум
  `MAX_SHIELD = 5`.

Отрисовка в задаче **временная**: дуги над кораблём нет (032), шкалы нет (033); иконки
кораблей в правой части панели показывают `shield` (на старте 2, после двух ударов 0 при
живом корабле). Игра целиком играбельна; ощущение передышки 2 с оценивает владелец.

таймерный переход → действие) сохраняется.

Автомат: `active --hit, shield>0--> invulnerable --120 тиков--> active`;
`active --hit, shield=0--> down` (конечное, `stateTicks` растёт).

## Точки встраивания

- **Цикл обновления** — без новых шагов: порядок `Battle.update` прежний (player → wave →
  bonusField → `resolveCollisions` → `resolveBonusCollisions` → `updatePhase`). Меняется
  только поведение внутри `Player.hit/update` и источник роста (`addShield`).
- **Коллизии** — правило «одно попадание за тик» работает и дальше: после удара корабль
  `invulnerable`, `canBeHit = false` — так же, как раньше `down`.
- **Прицеливание волны** — `canBeTargeted` не меняется; корабль в `invulnerable` остаётся
  целью (раньше 1 с `down` давал передышку от прицела).
- **Рендер** — `drawShip` не меняется: `invulnerable` уже мигает, `down` — взрыв. Корабль
  просто не переносится в центр.
- **HUD** — `hudView` берёт `battle.player.shield`; `drawLives(ctx, view.shield)`.
- **Ввод/сцены** — `TitleScene` прокидывает `GameStart.shield` в `PlayScene`/`Battle`;
  `main.ts` — `params.shield`.

## Тестируемость

Вся логика — без canvas и rng (`Player` rng не использует), детерминированная:

- `Player`: диапазон конструктора; `hit()` при `shield > 0` / `= 0`; no-op в
  `invulnerable`/`down`; `invulnerable → active` ровно через `INVULNERABLE_TICKS`;
  позиция корабля и выстрелы сохраняются после удара; `down` не выходит ни через какое
  число тиков; `addShield` (рост, `false` на максимуме и в `down`, состояние не трогает);
  сценарии «2 удара пережиты, 3-й — down» и «с MAX_SHIELD — 5 и 6-й».
- `Battle`: game over через `GAME_OVER_DELAY_TICKS` при `shield: 0`; удар со щитом —
  `playing`; пороги (+1, сверх максимума пропадает); таран на максимуме через порог —
  `max → max−1 → max`; таран при `shield: 0` через порог — всё равно `over`; капсула `L`
  (+1 / +500); удар и капсула в одном тике; переворот кейса `:512–535` по В7.
- `collisions`: прежние правила на щите; таран в щит даёт `Kill { inFlight: true }`.
- Рендер (мок-контекст): взрыв при `shield: 0`; мигание на месте попадания; HUD рисует
  `shield` иконок.
- dev-params, dev-snapshot, сцены — через существующие помощники.

Только глазами (`acceptance.md`, `/qa`): удар не убивает, корабль мигает на месте; третий
удар со старта — game over; иконки = уровень щита (не баг); передышка 2 с.

## Зависимости и ограничения

- Задача опирается на готовые 005–007; других задач до неё не нужно.
- 032/033 зависят от этой задачи: `LIVES_ZONE`, `LIVES_ICON_SLOTS`, `LIFE_ICON_*`,
  `drawLives`, `LIFE_ICON_SPRITE` в 031 **намеренно остаются** — это исключения поиска.
- Цикл импортов: `art.ts` в 031 не трогается — риска TDZ (`art → player → ship → art`)
  здесь нет.
- Детерминизм: порядок `BONUS_KINDS` тот же; поведение с тем же seed совпадает со старым
  только до первого попадания (корабль больше не исчезает и не переносится) — ожидаемо.
  Тест `play-scene.test.ts:300–311` сравнивает сцену с эталонным `Battle` — обе стороны
  строятся одинаково, сломаться не должен.
- Объём правки тестов большой (≈200 мест): главный риск — механическая замена ожиданий.
  Дизайн требует разбирать каждый кейс по смыслу («попадание засчитано» / «гибель» /
  «неуязвимый»). После правок — поиск по `src/` (`'life'`, `lives`, `START_LIVES`,
  `MAX_LIVES`, `DOWN_TICKS`, `addLife`, `EXTRA_LIFE`, `extraLives`) с исключениями 033 и
  `title-scene.ts:32`.
- Баланс: передышка меньше прежней (2 с вместо 3 с, корабль всё время в прицеле, остаётся
  под пикирующей группой) — подстройка одной константой `INVULNERABLE_TICKS`, решение — на
  приёмке.
- Вне `/do`: `.claude/agents/tester.md` (`?lives=N` → `?shield=N`) правит основная сессия
  с согласия владельца; без этого `/qa` не сможет стартовать с `?shield=0`.
- Временное расхождение: пункт HUD в `game-design.md` до 033 говорит про «иконки жизней».

   месте»).
