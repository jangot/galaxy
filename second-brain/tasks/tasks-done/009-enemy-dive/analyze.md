005–008 в рабочем дереве (`npm test` — 213 тестов зелёные, `typecheck` чистый).
Рамка — согласованный `design.md` фичи 002 (пункт 5 нарезки, «Уточнения для

## Общее описание функциональности

Строй перестаёт быть мишенью-тиром: через 3 с после начала уровня 1 (В1) враги
начинают по одному вылетать. Крайний враг ряда (самый левый или самый правый из стоящих
в строю) «отклеивается» — короткая дуга вверх-наружу, потом пикирует прямо вниз
(в этой задаче без прицеливания — оно в 010). Пролетев низ экрана, враг появляется над
верхним краем, над своим слотом, и опускается на своё место в покачивающемся строю,
догоняя слот по X. Пока враги не стреляют (012) и не таранят (011) — проходят сквозь
корабль. Сбить врага можно в любой фазе полёта.

Сложность по уровням: уровень 1 — одиночные вылеты раз в 3 с, пике 1 px/тик; уровень 2
— до 2 вылетов одновременно, пике 2 px/тик; новый уровень 3 — как 2, но строй качается
вдвое быстрее и вылеты чаще (стрельба уровня 3 — в 012).

Ощущение: враги «живые», игрок стреляет по движущимся целям; строй редеет и с флангов,
вылетевший враг возвращается без рывка. **Дугу вылета утверждает владелец глазами.**

## Модели данных и состояние

**Enemy** (расширение `src/game/enemy.ts`) — автомат:

| Состояние              | Движение за тик (`update`)                                                                                                 | `isAlive` | `isOut`                                                                                                                  | Переход                                                                |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------- | --------- | ------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| `formation`            | позиция = слот (как сейчас)                                                                                                | да        | нет                                                                                                                      | `startDive(order)` → `diving`; `kill()` → `exploding`                  |
| `diving`, фаза peel    | сегмент `PEEL_SEGMENTS` по `stateTicks`: `x += vx * side`, `y += vy` (целые px/тик); зажим `x ∈ [0, SCREEN_WIDTH - width]` | да        | да                                                                                                                       | после `P = Σ ticks` тиков — фаза `descend` (то же состояние)           |
| `diving`, фаза descend | `y += diveSpeed * dt` (`vx = 0` в 009); зажим X; затем проверка `y >= SCREEN_HEIGHT`                                       | да        | да                                                                                                                       | `y >= SCREEN_HEIGHT` → `returning`: `y = -height`, `x = slotX` текущий |
| `returning`            | шаг `step = 1`: если `                                                                                                     | slotX - x | <= step`и`slotY - y <= step`→ встать ровно в слот; иначе`y = min(y + step, slotY)`, `x += clamp(slotX - x, -step, step)` | да                                                                     | да  | в слоте → `formation` (`stateTicks = 0`, `sortieId = null`); `kill()` → `exploding` |
| `exploding` / `dead`   | без изменений (008)                                                                                                        | нет       | нет                                                                                                                      | как в 008                                                              |

- `startDive(order)` — только из `formation`, иначе игнор. Ставит `diving`,
  `stateTicks = 0`, запоминает `sortieId`, `side`. В тике вызова враг уже стоит в слоте
  этого тика (директор работает после `enemy.update`); первый шаг peel — в следующем
  `update`.
- **Тики фаз (по «Уточнениям»):** `startDive` в тике `N`; тики `N+1 … N+P` — peel
  (`stateTicks = 1 … P`); тик `N+P+1` — первый тик descend. Фазу и текущий сегмент
  удобно выводить из `stateTicks` (`stateTicks ≤ P` — peel), отдельный счётчик не
  нужен — это решение плана.
- `sortieId` — `number | null`, `null`, когда враг не `isOut` (в т. ч. после `kill()`
  в полёте — сбитый враг освобождает слот лимита вылетов). `side` хранится внутри.
- `isAlive` расширяется на `diving | returning` — тем самым правило 1 коллизий
  (выстрел игрока × живой враг) автоматически действует на врагов в полёте; правка
  `collisions.ts` не нужна.
- `stateTicks` — «Правило тиков переходов»: `update` сначала `++`, затем проверка
  перехода по таймеру, затем поведение. В `diving` таймерного перехода между
  состояниями нет (фаза — внутри), `diving → returning` и `returning → formation` —
  по позиции, внутри поведения тика.

**Константы `enemy.ts`:**

| Константа       | Значение                                                                      | Источник                     |
| --------------- | ----------------------------------------------------------------------------- | ---------------------------- |
| `STEER_SPEED`   | 60 px/с (1 px/тик) — в 009 используется только как шаг X в `returning`        | дизайн                       |
| `RETURN_SPEED`  | 60 px/с (1 px/тик) — шаг Y в `returning`                                      | дизайн                       |
| `PEEL_SEGMENTS` | старт: `[{4, vx 1, vy -1}, {4, vx 1, vy 0}, {6, vx 1, vy 1}]` для `side = +1` | «Стартовые визуальные числа» |

`PEEL_SEGMENTS`: `P = 14` тиков, суммарно `+14` px наружу и `+2` px по Y (вверх 4, вниз
6). Ограничения: `ticks` целое ≥ 1, `vx`/`vy` целые, первый `vy < 0`, последний
`vy > 0`, `vx ≥ 0`, `max vy ≤ 3`. Экспортируется вместе с типом `PeelSegment`.

**Типы:** `DiveOrder { sortieId, side: -1 | 1 }` (без `shots` — 012, без `aimOffsetX` —
013); `EnemyEnv { diveSpeed }` (без `targetX` — 010); `EnemyState` += `'diving' |
'returning'`. `Enemy.update(dt, env)` — `void` (возвращает `boolean` с 012).

**AttackDirector** (новый `src/game/attack-director.ts`):

- Данные: `timer` (тики до следующего вылета), `nextSortieId`; из `LevelConfig` —
  `diveIntervalTicks`, `maxSorties`.
- Старт: `timer = firstDiveDelayTicks`. Каждый `update`: `timer > 0` → `timer--`; если
  `timer === 0` и число активных вылетов (различные `sortieId` у врагов с `isOut`)
  `< maxSorties` → `selectSortie`; нашёлся — `startDive` всем участникам (в 009 —
  один), `nextSortieId++`, `timer = diveIntervalTicks`; не нашёлся или лимит занят —
  ждать с `timer = 0` (вылет в первом же тике, когда станет можно).
- Отсчёт: при `firstDiveDelayTicks = 180` вылет происходит в 180-м вызове `update`
  волны (3,0 с), первый шаг peel — в 181-м.
- `selectSortie(enemies, cols, sortieId, rng)` — чистая функция, `Sortie { members,
orders }` или `null`. Кандидаты: для каждого ряда — самый левый (`side = -1`) и самый
  правый (`side = +1`) враг в состоянии `formation`; если такой в ряду ровно один —
  один кандидат, `side = 2 * col + 1 < cols ? -1 : 1`. Порядок списка — ряды сверху
  вниз, в ряду левый, затем правый; выбор `randomInt(rng, 0, n)`. В 009 все виды
  (`drone`/`striker`) — одиночки; группы `raider` — 013.
- Порядок `wave.enemies` уже row-major (`parseLayout`), так что «крайние в ряду»
  выводятся одним проходом без сортировки.

**LevelConfig** — новые обязательные поля: `diveSpeed` (px/с, целые px/тик),
`firstDiveDelayTicks`, `diveIntervalTicks`, `maxSorties`.

| Уровень  | `layout`            | `swaySpeed` | `diveSpeed` | `firstDiveDelayTicks` | `diveIntervalTicks` | `maxSorties` |
| -------- | ------------------- | ----------- | ----------- | --------------------- | ------------------- | ------------ |
| 1        | как сейчас (3 ряда) | 15          | 60          | 180                   | 180                 | 1            |
| 2        | как сейчас (4 ряда) | 15          | 120         | 150                   | 150                 | 2            |
| 3 (нов.) | как 2               | 30          | 120         | 120                   | 120                 | 2            |

Тестовые таблицы (`ONE_CORNER_ENEMY`, `TWO_LEVELS`): `diveSpeed = 60`,
`firstDiveDelayTicks = 1_000_000`, `diveIntervalTicks = 1_000_000`, `maxSorties = 1` —
вылетов в тестах сцены/боя нет.

**Ориентиры по длительности (уровень 1, `drone` ряда 1):** `slotY = 46`; peel 14 тиков;
descend от `y = 48` до `240` — 192 тика; возврат от `y = -8` до `46` — 54 тика. Вылет
целиком ≈ 260 тиков (≈ 4,3 с) — дольше интервала 180, поэтому на уровне 1 при
`maxSorties = 1` директор фактически ждёт возврата (или гибели) вылетевшего. На уровнях
2–3 descend ≈ 96 тиков.

## Точки встраивания

- **`Wave.update(dt)`** (сигнатура в 009 не меняется; `targetX` — 010):
  `formation.update(dt)` → `enemy.update(dt, env)` для каждого →
  `director.update(enemies, formation.cols, rng)`. `env = { diveSpeed: config.diveSpeed }`
  — можно создать один раз в конструкторе (объект неизменяемый), чтобы не аллоцировать
  на каждого врага каждый тик.
- **Конструктор `Wave`:** `_rng` → хранимый `rng`; создаётся `AttackDirector(config)`.
- **`Battle`:** не меняется — уже вызывает `wave.update(dt)` и `resolveCollisions` после
  движения; летящие враги коллизятся по итоговым позициям тика.
- **Рендер:** не меняется. Слои «выстрел → враги → корабль»: пикирующий враг проходит
  под кораблём (корабль рисуется поверх) — сквозной пролёт выглядит естественно.
- **Ввод, HUD, сцены:** не затрагиваются.

## Тестируемость

Всё поведение задачи — чистая логика на `dt` и `Rng`, без canvas.

- **`enemy.test.ts`:**
  - `startDive` из `formation` → `diving`, `stateTicks = 0`, `isOut`, `sortieId`; в тике
    вызова позиция не меняется, первый шаг — в следующем `update`;
  - peel за `P` тиков проходит ровно `Σ(vx·side, vy)` (`toBe`), зеркально для `side = ±1`;
  - зажим X в peel: враг, поставленный у края экрана прямой установкой `x` после
    `startDive` (или у крайнего столбца при `-SWAY_RANGE`), не выходит за `[0, SCREEN_WIDTH - width]`;
  - descend: тик `P+1` — первый шаг `diveSpeed * dt` вниз, X не меняется;
  - `y >= SCREEN_HEIGHT` → `returning` в том же тике, `y = -height`, `x = slotX`;
  - возврат точно в слот → `formation`, `sortieId === null`; затем снова следует за слотом;
  - возврат при уехавшем по X слоте: враг доходит до `slotY` раньше, не проходит ниже
    `slotY` и всё равно заканчивается в `formation` (сдвинуть строй через
    `formation.update` или взять `swaySpeed` 30);
  - `kill()` из `diving` и `returning` → `exploding` → `dead`; `sortieId === null`,
    `isOut === false`;
  - `startDive` вне `formation` (в полёте, `exploding`, `dead`) — игнор;
  - ограничения `PEEL_SEGMENTS` (целые, первый вверх, последний вниз, `vx ≥ 0`, `max vy ≤ 3`).
- **`attack-director.test.ts`** (враги на маленьких раскладках через `Wave` или
  `Enemy` + `Formation`; состояние задаётся `startDive`/`kill`):
  - кандидаты — только крайние в `formation`; вылетевший/взорванный — не кандидат, его
    сосед становится крайним; одиночка в ряду — один кандидат, `side` по формуле (включая
    «ровно посередине — вправо»);
  - порядок кандидатов и выбор — подменой `rng` (`() => 0`, `() => 0.999…`) — первый/последний;
  - пустой список → `null`;
  - таймер: первый вылет ровно на `firstDiveDelayTicks`-м `update`, следующий — через
    `diveIntervalTicks`; лимит `maxSorties` держится; при освобождении (возврат или
    `kill`) — вылет в том же тике, если таймер уже 0; `sortieId` растут;
  - детерминизм: одинаковый seed → одинаковая последовательность выбранных; разные
    фиксированные seed → разная.
- **`wave.test.ts`:** две волны на `LEVELS[1]` с одним seed после N тиков (N с
  несколькими вылетами и возвратами, напр. 600) совпадают по `x/y/state` всех врагов;
  директор после врагов — враг, получивший приказ, в этом тике стоит в слоте этого тика.
- **`levels.test.ts`:** точные строки уровней 1–3 (по «Уточнениям»), инварианты для
  каждой строки: `isAllowedSpeed(diveSpeed)` и `diveSpeed * TICK_SECONDS` целое;
  `Number.isInteger` и `≥ 1` для таймеров и `maxSorties`; `swaySpeed < STEER_SPEED`;
  туннелирование `SHOT_SPEED·dt + maxDown < SHOT_HEIGHT + minEnemyHeight`, где
  `maxDown = max(diveSpeed·dt, max vy PEEL_SEGMENTS, RETURN_SPEED·dt)`, `minEnemyHeight`
  — минимум высот `ENEMY_KINDS` (сейчас `4 + 2 < 4 + 8`). Проверено в double:
  `60/120/180 · (1/60)` = `1/2/3` ровно.
- **`collisions.test.ts`:** выстрел игрока сбивает врага в `diving` (прямая установка
  позиции).
- **Только глазами:** форма дуги («отклеивание»), плавность пике, возврат без рывка,
  ощущение частоты вылетов на уровнях 1–3 (`?level=3`). **Владелец утверждает дугу.**

## Зависимости и ограничения

- Зависит от 008 (в рабочем дереве; ждёт только приёмки вида взрыва — на 009 не влияет).
- **ADR 002/003:** peel и descend — целые px/тик; X врага остаётся дробным (наследуется
  от слота с покачиванием, шаги целые — дробная часть сохраняется, `floor` при
  отрисовке не дёргает). В `returning` сходимость к дробному `slotX` точная: все числа —
  двоичные дроби, шаг 1 px больше сдвига слота за тик (`swaySpeed < STEER_SPEED`).
- Единицы `PEEL_SEGMENTS` — px/тик (без `dt`), остальные скорости — px/с × `dt`.
  Смешение задано дизайном; в коде стоит явно подписать.
- **Таймеры** — целые тики (ADR 003): `firstDiveDelayTicks`, `diveIntervalTicks`.
- Производительность: директор — один проход по ≤ 38 врагам за тик плюс подсчёт
  активных вылетов (≤ `maxSorties` различных id); пренебрежимо.
- **Существующие тесты, которые придётся тронуть** (механически): все литералы
  `LevelConfig` (`levels.test.ts` ×2, `wave.test.ts` ×3, `collisions.test.ts` ×1) — новые
  поля обязательные, иначе `tsc`; все вызовы `enemy.update()` без аргументов
  (`enemy.test.ts`, `collisions.test.ts`). Разумно завести в тестах хелпер «пассивного»
  конфига — решение плана.
- Тесты, которые гоняют `LEVELS` долго, отсутствуют (проверено: `battle.test.ts`,
  `battle-render.test.ts`, `play-scene.test.ts` на `LEVELS` — 0–1 тик), поэтому
  появление вылетов на 180-м тике их не ломает.
- Пикирующий враг сквозь корабль: таран — 011; рендер рисует корабль поверх.
- Выстрел игрока не может сбить невидимого врага над экраном в `returning`: выстрел
  стоит на `y = 204 − 4k ≥ 0` в момент коллизий (ушедший за верх удаляется раньше), а
  возвращающийся враг до появления на экране занимает `y < 0` — пересечения нет.
- Враг, вернувшийся в слот в тике `T`, в том же тике может снова стать кандидатом
  (директор после врагов) — допустимо по дизайну.
- `isCleared` при последнем враге в полёте ждёт, пока его собьют: враг циклит
  «пике → возврат» — ожидаемо.

## Открытые вопросы

- **Утверждение дуги вылета владельцем** — после реализации, глазами (`PEEL_SEGMENTS`
  — стартовое предложение из «Уточнений»). Не блокирует анализ и план.
- Расхождений дизайна с кодом не найдено: сигнатуры 005–008 совпадают с ожидаемыми
  дизайном (`Wave(config, _rng)`, `Enemy.update()` без параметров, `isAlive` только
  `formation`, `levels.test` пока без инвариантов туннелирования — они появляются здесь).
- Отдельных задач выносить не нужно.
