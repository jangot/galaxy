# Задача: Пикирование: вылет и возврат

## Суть задачи

Враги начинают вылетать из строя: крайние враги с флангов отклеиваются по дуге, пикируют вниз и возвращаются в свой слот сверху. Пока не стреляют и не таранят (проходят сквозь корабль).

## Детали и требования

- `attack-director.ts`: кандидаты — крайние враги любого ряда (`side` одиночки — по формуле из «Уточнений»), таймеры, лимит `maxSorties`, выбор через `Rng`. Сигнатура в этой задаче — `selectSortie(enemies, cols, sortieId, rng)`: параметр `config` появляется в 012 (нужен только для числа выстрелов), иначе `noUnusedParameters`. `DiveOrder { sortieId, side }` — `shots` в 012, `aimOffsetX` в 013.
- Порядок в `Wave.update`: строй → враги → директор.
- `Enemy`: `diving` (`peel` с зажимом по X, `descend` прямо вниз), `returning` с зажимом `y` по `slotY` (шаг — по «Уточнениям»); `isOut`, `sortieId`; `EnemyEnv { diveSpeed }`; `STEER_SPEED`, `RETURN_SPEED`; экспорт `PEEL_SEGMENTS` (ограничения и стартовый маршрут — в «Уточнениях»).
- Поля `diveSpeed`, `firstDiveDelayTicks` (180 тиков = 3 с на уровне 1), `diveIntervalTicks`, `maxSorties`; уровни 1–3 по В1: пике 60/120/120 px/с, покачивание 15/15/30 px/с (уровень 3 добавляется здесь, стрельба у него — в 012). Тестовые таблицы получают пассивные значения (`firstDiveDelayTicks = 1_000_000` и т. д. — см. «Уточнения»).
- Инварианты таблицы: `swaySpeed < STEER_SPEED`; отсутствие туннелирования «выстрел игрока × враг» по максимальной скорости вниз.

Точные интерфейсы, числа и порядок тика — в дизайне фичи (см. «Контекст»).

## Критерии готовности

- Тесты `enemy`, `attack-director`, детерминизм `wave`.
- Глазами: враги отклеиваются, пикируют, возвращаются, сбиваются в полёте.
- **Владелец утверждает дугу вылета.**
- Все проверки проходят: `format:check`, `lint`, `typecheck`, `test`, `build`.
- Игра остаётся рабочей; новые модули дописаны в `second-brain/architecture/overview.md`.
