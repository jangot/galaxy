# Анализ: Поражение игрока тараном

## Общее описание функциональности

Первое поражение игрока в игре. Пикирующий (или возвращающийся) враг, коснувшийся
корабля, гибнет сам (обычный взрыв врага, решение В6) и уничтожает корабль. Дальше
(В5):

1. **`down`, 1 с (60 тиков).** На месте корабля 16 тиков играет тот же взрыв, что у
   врагов, затем пусто. Ввод игнорируется: корабль не двигается, огонь не работает.
   Выстрел, выпущенный до гибели, летит дальше и может сбить врага. Враги теряют цель:
   `striker` летит прямо вниз, пока корабля нет; `drone`, начавший `descend` в это время,
   весь `descend` летит прямо вниз.
2. **`invulnerable`, 2 с (120 тиков).** Корабль появляется по центру (`SHIP_START_X`) и
   мигает (4 тика виден / 4 скрыт). Он управляем и стреляет, его можно брать в цель, но
   коллизии с ним не проверяются: враги проходят насквозь.
3. **`active`.** Обычное состояние, таран снова действует.

Уровень не перезапускается, строй живёт дальше. Жизней, Game Over, счёта нет — это
отдельная фича. Вражеских выстрелов пока нет (задача 012), так что таран — единственный
способ поразить игрока.

## Модели данных и состояние

**Player — новый автомат корабля** (автомат выстрела из 001 не меняется):

| Состояние      | Вход                                            | Поведение `update`                                                    | `canBeHit` | `canBeTargeted` | Рендер корабля                                                |
| -------------- | ----------------------------------------------- | --------------------------------------------------------------------- | ---------- | --------------- | ------------------------------------------------------------- |
| `active`       | старт; `invulnerable` по `INVULNERABLE_TICKS`   | как в 001: движение → полёт выстрела → огонь                          | да         | да              | спрайт                                                        |
| `down`         | `hit()` из `active` (в коллизиях)               | только полёт выстрела (и его удаление за верхом); intent игнорируется | нет        | нет             | кадр взрыва при `stateTicks < EXPLOSION_TICKS`, иначе ничего  |
| `invulnerable` | `down` по `DOWN_TICKS`; `ship.x = SHIP_START_X` | как `active`                                                          | нет        | да              | спрайт, если `Math.floor(stateTicks / BLINK_TICKS) % 2 === 0` |

- Новые поля/геттеры: `state: ShipState`, `stateTicks`, `canBeHit` (`state === 'active'`),
  `canBeTargeted` (`state !== 'down'`), метод `hit()` (только из `active`, иначе ничего;
  выстрел **не** снимает).
- «Правило тиков переходов» (дизайн): `hit()` ставит `stateTicks = 0`; `update` сначала
  `stateTicks++`, затем переход по таймеру, затем поведение нового состояния. Из этого:
  - `hit()` в тике `T` → тики `T+1 … T+59` — `down`; в тике `T+60` `stateTicks` дошёл
    до 60 → `invulnerable`, `stateTicks = 0`, `ship.x = SHIP_START_X`, и intent этого же
    тика уже обработан (сдвиг на шаг, огонь);
  - `invulnerable → active` в тике `T+180`; коллизии этого тика уже действуют.
  - В тике `T` (тик `hit()`) рендер уже рисует `down` со `stateTicks = 0` — кадр взрыва 0.
  - В `active` `stateTicks` тоже растёт (рендер его не читает) — без ограничения, это
    безопасно.
- Корабль в `down` стоит, где его поразили: взрыв рисуется в этой точке; `x` меняется
  только в тике перехода в `invulnerable`.

**Константы:**

| Константа            | Где                | Значение                                            | Источник                             |
| -------------------- | ------------------ | --------------------------------------------------- | ------------------------------------ |
| `SHIP_START_X`       | `ship.ts`          | `Math.floor((SCREEN_WIDTH - SHIP_WIDTH) / 2)` = 120 | дизайн; общий с конструктором `Ship` |
| `DOWN_TICKS`         | `player.ts`        | 60 (1 с)                                            | В5                                   |
| `INVULNERABLE_TICKS` | `player.ts`        | 120 (2 с)                                           | В5                                   |
| `BLINK_TICKS`        | `battle-render.ts` | 4                                                   | визуальное, «Уточнения»              |
| `EXPLOSION_TICKS`    | `enemy.ts` (есть)  | 16 (`EXPLOSION_FRAMES.length × 8`)                  | 008; инвариант `< DOWN_TICKS`        |

Мигание при `INVULNERABLE_TICKS = 120` и `BLINK_TICKS = 4`: 15 циклов «4 видим / 4 нет»,
тик 0 — видимый, тики 116–119 — скрыты, в тике 120 корабль уже `active` (виден).

**Взрыв корабля — позиция.** По правилу «Уточнений»: кадр центрируется в прямоугольнике
15 × 16: кадр 0 (11 × 9) — `(x + 2, y + 3)`, кадр 1 (13 × 9) — `(x + 1, y + 3)`, где
`x = Math.floor(ship.x)`, `y = SHIP_Y`. Кадр — `EXPLOSION_FRAMES[floor(stateTicks / EXPLOSION_FRAME_TICKS)]`.

**Правило 3 коллизий (таран).** После правила 1 (выстрел игрока × враги), если
`player.canBeHit`: первый по порядку `wave.enemies` враг с `isOut` (`diving | returning`;
`isOut` подразумевает живого), чей прямоугольник `overlaps` с прямоугольником корабля
(`ship.x, ship.y, SHIP_WIDTH, SHIP_HEIGHT`) → `enemy.kill()`, `player.hit()`, и на этом
всё (после `hit()` `canBeHit = false`, остальные враги проходят насквозь). Враг в
`formation` не таранит; враг, сбитый выстрелом игрока в этом же тике, уже `exploding` —
не таранит (порядок правил — в пользу игрока).

## Точки встраивания

- **`Player.update`** — в начале: `stateTicks++` и переходы по таймеру (`down →
invulnerable` с возвратом в центр; `invulnerable → active`). Затем: в `down` — только
  полёт выстрела и удаление ушедшего за верх; иначе — прежний порядок 001 (движение →
  выстрел → огонь).
- **`Battle.update`, шаг 2** — сейчас `targetX` всегда центр корабля (комментарий в
  `src/game/battle.ts` прямо отсылает к 011). Становится `player.canBeTargeted ? центр :
null`. Вычисляется после `player.update`, до коллизий, поэтому в тике `hit()` волна
  ещё видела цель, `null` — с тика `T+1`; в тике возрождения цель — уже центр нового
  положения корабля.
- **`resolveCollisions`** — сейчас функция делает `if (!shot) return;` в самом начале
  (`src/game/collisions.ts`). Правило 3 должно выполняться и без выстрела игрока —
  правило 1 нужно выделить так, чтобы ранний выход не обрывал таран. Место для правила 2
  (012) — между ними, по «Поток тика».
- **`drawBattle`** — последний слой (корабль): вместо безусловного `drawSprite` —
  выбор по `player.state`/`stateTicks`. Выстрел игрока рисуется как раньше, в любом
  состоянии корабля.
- **`Ship` конструктор** — значение по умолчанию `x = SHIP_START_X` вместо формулы.
- `PlayScene`, `TitleScene`, `main.ts`, `Wave`, `Enemy`, движок — не меняются.

## Тестируемость

Unit-тестами (детерминированно, через `dt = TICK_SECONDS` и прямую установку координат):

- **`Player`**: весь автомат — `hit()` вызывается напрямую, тики считаются точно по
  «Правилу тиков переходов». Два теста тика возрождения — обязательны (критерий
  готовности). Корабль сдвигается от центра до `hit()`, чтобы проверка `SHIP_START_X`
  была содержательной.
- **`collisions`**: враг ставится в `diving`/`returning` через `startDive` (+ `update`
  с `targetX: null` для `returning`, как в существующих тестах), координаты — прямой
  установкой над кораблём (`SHIP_Y = 208`, корабль по умолчанию `x = 120`, 15 × 16).
- **`battle-render`**: `battle.player.hit()` напрямую + `battle.update(IDLE)` нужное
  число раз на `ONE_CORNER_ENEMY` (вылетов нет); сравнение полных списков вызовов, как в
  существующих тестах. Инвариант `EXPLOSION_TICKS < DOWN_TICKS`.
- **`battle`** (по желанию): `canBeTargeted` → `targetX = null` проверяется косвенно —
  `striker` в `descend` при `down` не меняет `x`.

Только глазами (`npm run dev`): таран взрывает корабль и врага одновременно; взрыв
корабля читается; корабль появляется по центру и заметно мигает; враги проходят сквозь
мигающий корабль; через 2 с таран снова работает.

## Зависимости и ограничения

- Зависит от 010 (прицеливание, ветка `targetX === null` в `Enemy` уже есть и
  покрыта тестами `enemy.test.ts`) — менять `Enemy` не нужно.
- Порядок тика `Battle` не меняется: игрок → волна → коллизии (только `playing`) → фазы.
  В фазе `cleared` коллизий нет; корабль в `down`/`invulnerable` при смене уровня просто
  продолжает свой таймер — состояния независимы (крайний случай дизайна).
- Таймеры — целые тики (ADR 003), `hit()`/переходы не зависят от `dt`.
- Импорты без циклов: `collisions → ship` (значения `SHIP_WIDTH`/`SHIP_HEIGHT`), `Player`
  — по-прежнему `import type`; `battle-render` уже импортирует `enemy`/`enemy-art`.
  `player → ship` уже есть (для `SHIP_START_X`).
- Производительность: правило 3 — один проход по врагам (≤ 55) за тик, пренебрежимо.
- Риск: убрать ранний `return` из `resolveCollisions` аккуратно — правило 1 должно
  по-прежнему ничего не делать без выстрела (тест «does nothing without a shot»).
- Риск: `hit()` в `down`/`invulnerable` не должен сбрасывать `stateTicks` (иначе таран
  в `invulnerable` продлевал бы неуязвимость) — покрыть тестом.
