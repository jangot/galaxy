# Анализ: Стрельба пикирующих врагов

Код: ветка `feature/002-enemies-and-levels`, база `20da398` + незакоммиченные задачи 005–011
в рабочем дереве.

## Общее описание функциональности

С 3-го уровня враг, вылетевший из строя, в фазе `descend` (после дуги `peel`) стреляет
вниз по игроку: короткий вертикальный выстрел 1×4 своего (не белого) цвета летит строго
вниз со скоростью 240 px/с (4 px/тик — быстрее любого пикирования, поэтому выстрел сразу
«отрывается» от носа врага и всегда виден). На экране одновременно не больше 4 вражеских
выстрелов; лишний выстрел «пропадает» (В2). Попадание в корабль, пока он `active`,
поражает его так же, как таран: выстрел исчезает, корабль уходит в `down` → `invulnerable`
→ `active` (автомат из 011). В `down`/`invulnerable` выстрелы пролетают сквозь корабль.
Выстрел игрока и вражеский выстрел друг друга не сбивают. Когда уровень пройден (все враги
`dead`), оставшиеся вражеские выстрелы исчезают.

Рамка — согласованный `design.md` фичи 002 (пункт 8 нарезки, «Уточнения для реализации»,
строка 012 таблицы «Появление API по задачам»). Анализ уточняет его по коду, не
перепроектирует.

## Модели данных и состояние

**EnemyShot** (новый, `src/game/enemy-shot.ts`) — по образцу `Shot` из 001
(`src/game/shot.ts`), но отдельный класс (решение дизайна: другие владелец, направление,
граница исчезновения; `shot.ts` не трогаем).

| Что                 | Значение                                                          |
| ------------------- | ----------------------------------------------------------------- |
| `ENEMY_SHOT_WIDTH`  | 1                                                                 |
| `ENEMY_SHOT_HEIGHT` | 4                                                                 |
| `ENEMY_SHOT_SPEED`  | 240 px/с (4 px/тик, целое — ADR 002)                              |
| поля                | `readonly x` (фиксирован при вылете), `y` (публичный, мутируемый) |
| `update(dt)`        | `y += ENEMY_SHOT_SPEED * dt`                                      |
| `isOffscreen`       | `y >= SCREEN_HEIGHT` (весь выстрел ниже нижнего края)             |

**Enemy** (`src/game/enemy.ts`) — расширение:

| Что                         | Значение / правило                                                                                                                                                                                                               |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ENEMY_FIRE_INTERVAL_TICKS` | 20 (В2), экспорт                                                                                                                                                                                                                 |
| `DiveOrder.shots`           | новое обязательное поле (число выстрелов за вылет); `aimOffsetX` — не в этой задаче (013)                                                                                                                                        |
| `shotsLeft` (private)       | копия `order.shots` в `startDive`                                                                                                                                                                                                |
| тики выстрела               | `D, D+20, D+40, …`, где `D` — первый тик `descend` = `stateTicks === PEEL_TICKS + 1` (сейчас `PEEL_TICKS = 14`, т. е. 15-й `update` после `startDive`), пока `shotsLeft > 0`                                                     |
| условие                     | низ врага не ниже верха корабля: `y + height <= SHIP_Y` (`SHIP_Y = 208`, `ship.ts`), по позиции **после** сдвига этого тика; не выполнено — выстрел не делается (дальше враг только снижается, значит и последующие не делаются) |
| порядок внутри `descend`    | (первый тик — взять цель `fixed`) → сдвиг X/Y, зажим X → проверка ухода за низ (`→ returning`) → решение о выстреле. После перехода в `returning` в этом же тике выстрела нет (стрельба только в `descend`)                      |
| `update(dt, env)`           | возвращает `boolean`: `true` в тике выстрела (до 012 — `void`); при `true` `shotsLeft--` **независимо** от того, создаст ли `Wave` выстрел                                                                                       |
| в остальных состояниях      | `formation`, `peel`, `returning`, `exploding`, `dead` — всегда `false`                                                                                                                                                           |
| от цели не зависит          | стрельба не требует `targetX` (в `down` корабля враги тоже стреляют; выстрелы пролетают сквозь — коллизии не проверяются)                                                                                                        |

Позиция нового выстрела (считает `Wave`): `x = Math.floor(enemy.x) + Math.floor(enemy.width / 2)`
(целый столбец под центром нарисованного спрайта: drone 11 → +5, striker 13 → +6),
`y = enemy.y + enemy.height` (у носа). `enemy.y` в полёте целый (слоты по Y целые, peel и
`diveSpeed` — целые px/тик), `enemy.x` дробный (покачивание) — отсюда `floor`.

**LevelConfig** (`src/game/levels.ts`) — новое поле `diverShots` (выстрелов за вылет у
`drone`/`striker`, 0 — не стреляют). `raiderShots` — не в этой задаче (013).

| Уровень | `diverShots` |
| ------- | ------------ |
| 1       | 0            |
| 2       | 0            |
| 3       | 1            |

Тестовые таблицы (`test-levels.ts`, `PASSIVE`) — `diverShots = 0`.

**Wave** (`src/game/wave.ts`) — расширение:

| Что                | Правило                                            |
| ------------------ | -------------------------------------------------- |
| `MAX_ENEMY_SHOTS`  | 4 (В2), экспорт                                    |
| `shots` (getter)   | `readonly EnemyShot[]`, порядок — порядок создания |
| `removeShot(shot)` | убрать конкретный выстрел (попадание в корабль)    |
| `clearShots()`     | убрать все (вход в `cleared`)                      |

## Точки встраивания

- **Цикл:** `PlayScene.update` → `Battle.update(dt, intent)` — порядок не меняется
  (игрок → волна → коллизии в `playing` → фазы). `main.ts`, цикл, ввод — без изменений.
- **`Wave.update(dt, targetX)`** — новый порядок: покачивание строя → **полёт вражеских
  выстрелов и удаление ушедших за низ** → каждый враг `enemy.update` (вернул `true` и
  `shots.length < MAX_ENEMY_SHOTS` → новый `EnemyShot` из центра низа врага) → директор.
  Следствия: выстрел в тике появления не движется (рисуется и коллизится у носа), слот
  лимита, освобождённый уходом выстрела за низ, доступен в этом же тике.
- **`AttackDirector.update`** → `selectSortie(enemies, cols, config, sortieId, rng)` —
  `config` уже хранится в директоре (`this.config`).
- **`resolveCollisions`**: правило 1 (выстрел игрока × враги) → **правило 2**: если
  `player.canBeHit` — первый в порядке `wave.shots` выстрел, пересекающий корабль
  (`overlaps`, хитбокс корабля `SHIP_WIDTH × SHIP_HEIGHT` в `ship.x, ship.y`), удаляется
  (`wave.removeShot`), `player.hit()`; не больше одного за тик → правило 3 (таран) — уже
  проверяет `canBeHit`, поэтому после попадания выстрелом таран в этом тике не
  срабатывает (враг, который таранил бы, не гибнет и летит дальше — одно поражение за
  тик, как в дизайне).
- **`Battle.updatePhase`**: в ветке `playing → cleared` — `wave.clearShots()`. В `cleared`
  `wave.update` продолжает вызываться, но живых врагов нет — новых выстрелов не будет.
  Новая волна создаётся с пустым `shots`.
- **Рендер `drawBattle`**: слои — вражеские выстрелы (`ENEMY_SHOT_COLOR`, `fillRect`
  `floor(x), floor(y), 1, 4`) → выстрел игрока → враги → корабль. Выстрелы под
  спрайтами (как в 001).
- HUD нет.

## Тестируемость

Вся логика детерминирована (таймеры — целые тики, скорости — целые px/тик, `Rng` в
стрельбе не участвует) и тестируется без canvas.

- **`enemy-shot.test.ts`** — полёт, граница, целочисленность скорости.
- **`enemy.test.ts`** (враг из `newEnemyOf`, `startDive({ …, shots })`, `step`):
  - `update` возвращает `false` во всех тиках `peel` и `true` ровно в первом тике
    `descend` (`stateTicks === P + 1`);
  - при `shots = 3` — `true` в тиках `D`, `D + 20`, `D + 40`, больше — нет; между ними
    `false`;
  - `shots = 0` — ни разу за весь вылет;
  - ниже `SHIP_Y` — не стреляет (граница: `y + height === SHIP_Y` → стреляет, на 1 px
    ниже — нет; ставится прямой установкой `y` перед плановым тиком), и после этого
    плановые выстрелы не возобновляются;
  - в `formation`/`returning`/`exploding` — всегда `false`; новый вылет берёт `shots`
    нового приказа (счётчик не наследуется);
  - решение о выстреле — по позиции после сдвига этого тика.
- **`attack-director.test.ts`** — приказ несёт `shots === config.diverShots`.
- **`wave.test.ts`** (`passiveLevel` + ручной `startDive` на `wave.enemies`, `targetX = null`):
  - выстрел создаётся в тике `D` из `floor(enemy.x) + floor(width / 2)`,
    `y === enemy.y + enemy.height` (не сдвинут в тике появления), в следующем тике — `+4`;
  - лимит: 5 врагов одного ряда стартуют в одном тике с `shots ≥ 1` → в тике `D`
    создано ровно `MAX_ENEMY_SHOTS`, у пятого выстрел «пропал» (счётчик израсходован —
    через `shots = 1` у пятого: в `D + 20` он не стреляет);
  - слот лимита, освобождённый уходом за низ, доступен в том же тике: у полного набора
    одному выстрелу ставится `y` у нижнего края (`y` публичный), в этом же тике плановый
    выстрел другого врага создаётся;
  - ушедшие за низ удаляются; `removeShot`, `clearShots`;
  - детерминизм на `LEVELS[2]` (стреляющий уровень) — две волны с одним seed после N
    тиков совпадают и по выстрелам.
- **`collisions.test.ts`**: выстрел, пересекающий `active` корабль, удаляется и
  `hit()`; касание краями — нет; в `down`/`invulnerable` — выстрел остаётся, корабль
  не поражён; два пересекающих выстрела — удаляется только первый; выстрел и таран в одном
  тике — одно поражение (выстрел удалён, таранящий враг жив); выстрел игрока не
  взаимодействует с вражеским. Способ поставить выстрел: `EnemyShot.x` — `readonly`,
  публичного «добавить выстрел» у `Wave` нет (в дизайне его нет); выстрел получается
  честно — вылет с `shots ≥ 1` и `P + 1` тиков `wave.update`, затем прямой установкой
  `shot.y` и `ship.x` (публичные) выстрел подводится к кораблю. Добавлять тестовый API в
  `Wave` не нужно.
- **`levels.test.ts`** — инварианты строк `LEVELS` и туннелирование.
- **`battle.test.ts`** — `clearShots` при входе в `cleared` (вылет одинокого врага с
  `shots = 1` на `passiveLevel`, выстрел в полёте, затем `kill()` → через
  `EXPLOSION_TICKS` фаза `cleared`, `wave.shots` пусты; угловой враг далеко от столбца
  корабля — выстрел за 16 тиков не долетает до корабля и не задевает его).
- **`battle-render.test.ts`** — слой и цвет вражеского выстрела.
- **Только глазами** (`npm run dev`, `?level=3`): выстрелы видны, отрываются от носа врага
  (2 px/тик при `diveSpeed = 120`), цвет отличим от своего и от звёзд, попадание
  поражает корабль (взрыв, возрождение с миганием), в мигании выстрелы пролетают сквозь;
  при прохождении уровня выстрелы исчезают.

## Зависимости и ограничения

- Зависит от 011 (автомат корабля, `canBeHit`, `hit()`, правило 3) — в рабочем дереве есть.
- ADR 002: `ENEMY_SHOT_SPEED * TICK_SECONDS` — целое (4). ADR 003: интервал — целые тики.
- Туннелирования нет: за тик выстрел сдвигается на 4 px < `ENEMY_SHOT_HEIGHT +
SHIP_HEIGHT` = 4 + 16; корабль по Y не движется. Отрыв от врага: `4 - diveSpeed/60` ≥ 2
  px/тик на уровнях 1–3 (инвариант `ENEMY_SHOT_SPEED > diveSpeed`).
- Производительность: не больше 4 выстрелов, проверка × один корабль — пренебрежимо.
- Изменение сигнатур ломает компиляцию тестов: `DiveOrder.shots` обязателен (26 вызовов
  `startDive` в тестах), `selectSortie` получает `config` (3 вызова в тестах), `LEVELS`
  проверяется `toEqual` целиком — всё это правится в рамках задачи.
- Риск: `Enemy.update` теперь возвращает значение, а существующие вызовы его
  игнорируют — для TS и текущих правил ESLint это допустимо (правила на неиспользуемый
  результат для не-Promise нет).
- Риск порядка: создание выстрела должно идти после `enemy.update` этого врага (позиция
  после сдвига) и после полёта уже существующих выстрелов — иначе выстрел сдвинется в
  тике появления или лимит посчитается до удаления ушедших.
- Стрельба не зависит от `targetX`: в `down` враги стреляют, выстрелы пролетают (как в
  дизайне: «враги и выстрелы продолжают движение»).
- Границы задачи: `raiderShots`, `aimOffsetX`, группы — 013; `game-design.md` — 013;
  запись фичи в `second-brain/features/` не трогаем.
