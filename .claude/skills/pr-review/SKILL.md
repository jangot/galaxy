# Разбор PR перед мержем

Цель: собрать полную картину по PR и вынести на обсуждение то, что мешает мержу или
требует решения. **Скилл только смотрит:** код не меняет, на комментарии не отвечает,
треды не резолвит, не пушит и не мёржит.

## Аргументы

- **номер задачи** (`007`) → папка в `second-brain/tasks/` (`ls ... | grep '^{NNN}-'`);
  прочитать `description.md` и `plan.md`, чтобы понимать, что входит в задачу. PR —
  по текущей ветке.
- **номер PR** (`#12` / `12`) → этот PR.
- **пусто** → PR текущей ветки; задачу определить по контексту чата.

## Шаг 1. Найти PR

```bash
git remote get-url origin        # нет remote — сообщить и остановиться
git branch --show-current
git fetch origin
git status -sb
gh pr list --head <branch> --state open --json number,url,title,baseRefName,isDraft
```

- Открытого PR нет → сообщить (предложить `/commit`) и остановиться.
- Текущая ветка `main` и номер PR не передан → спросить, какой PR.
- Есть незапушенные коммиты / незакоммиченные правки → отметить в отчёте.

## Шаг 2. Состояние PR

```bash
gh pr view <N> --json number,title,url,state,isDraft,baseRefName,headRefName,mergeable,mergeStateStatus,reviewDecision,commits,files,additions,deletions
gh pr checks <N>
```

- **CI:** что упало / идёт; для упавших — `gh run view <run-id> --log-failed`, причина.
- **Конфликты / отставание:** `mergeable`, `mergeStateStatus` (`DIRTY`, `BEHIND`, `BLOCKED`).
- **Ревью:** `reviewDecision`; **Draft**.
- **Состав PR:** сверить файлы с `plan.md` задачи — лишние/пропущенные в отчёт.

## Шаг 3. Все комментарии

```bash
OWNER_REPO=$(gh repo view --json nameWithOwner -q .nameWithOwner)
gh api --paginate repos/$OWNER_REPO/issues/<N>/comments
gh api --paginate repos/$OWNER_REPO/pulls/<N>/reviews
gh api graphql -f query='
query($o:String!,$r:String!,$n:Int!){repository(owner:$o,name:$r){pullRequest(number:$n){
  reviewThreads(first:100){nodes{isResolved isOutdated path line originalLine
    comments(first:50){nodes{author{login __typename} body createdAt url}}}}}}}' \
  -f o=<owner> -f r=<repo> -F n=<N>
```

Авторы:
- **Агенты:** REST — `user.type == "Bot"` / логин с `[bot]`; GraphQL —
  `author.__typename == "Bot"`. Служебные комментарии-прогресс и чеклисты — шум;
  ценность — в находках.
- **Люди:** комментарии людей **всегда** попадают в отчёт.

Сверять дату комментария с датами коммитов: старые находки могли быть уже исправлены.

## Шаг 4. Проверить каждый комментарий по коду

1. Открыть текущий код в указанном месте (`path`/`line`; у устаревших — `originalLine`).
2. Оценить по существу: код вокруг, вызывающие. Ботов не принимать на веру.
3. Категория:
   - 🔴 **Блокер** — реальная ошибка: неверная логика, падение, сломанная игровая
     механика, недетерминизм в логике, утечки (слушатели, rAF), секреты.
   - 🟡 **Обсудить** — спорное решение, вопрос человека, выбор владельца.
   - ⚪ **Не блокер** — стиль, nit.
   - ✅ **Уже решено** — исправлено последующими коммитами.
   - ❌ **Ложное** — проверка показала, что замечание неверно (коротко: почему).
   - ↗ **Вне задачи** — про соседний/старый код. Одна строка.

## Шаг 5. Отчёт

По-русски, коротко:

1. **Готов ли PR к мержу:** да / нет — одной фразой с главной причиной.
2. **Состояние:** CI, конфликты, approve, draft, локальные незапушенные изменения.
3. **На обсуждение (🔴 и 🟡)** — автор и ссылка; суть; что показала проверка
   (`path:line`); рекомендация.
4. **Остальное** — ⚪ / ✅ / ❌ / ↗ по одной строке.

Дальше — ждать решения пользователя. Действия — только по явной команде.

## Заметки

- Ничего не публиковать в PR без явной просьбы.
- Тексты для PR — на английском.
- Замечания, расширяющие scope, — ↗, не продвигать.
