# Прогон полного конвейера analyze → plan → do → fix-tests

Цель: последовательно выполнить стадии конвейера для задачи, запуская **отдельный
субагент на каждый шаг** с изолированным контекстом (`Agent` tool,
`subagent_type: general-purpose`); каждый субагент внутри вызывает соответствующий
скил через `Skill` tool.

Оркестратор (текущий агент) сам код не пишет — только связывает шаги. Обмен между
шагами идёт **через файлы в папке задачи** (`description.md`, `analyze.md`, `plan.md`).

## Аргументы

- `$ARGUMENTS` — номер задачи (обязателен). Формат: число, напр. `007`.

Если номер не передан — сообщить пользователю и остановиться. Не угадывать.

## Подготовка

- Корень проекта: `/Users/jangot/Projects/private/galaxy`.
- Найти папку задачи: `ls second-brain/tasks/tasks/ second-brain/tasks/tasks-done/ | grep '^{NNN}-'`.
- Запомнить полный путь к папке — он нужен для проверок и записи `error.md`.
- Если папка не найдена — сообщить пользователю и остановиться.

## Границы задачи

Если субагент сообщает, что для задачи нужна самостоятельная доработка вне её рамок —
не расширять задачу молча: остановить конвейер, сообщить пользователю, предложить
завести отдельную задачу.

## Как запускать шаг

Для каждого шага — **Agent tool** с:

- `subagent_type`: `general-purpose`
- `description`: короткая строка (3–5 слов), напр. `Analyze task 007`
- `prompt`: **полный самодостаточный текст** из шаблона ниже (подставить `{NNN}`)

Субагент **не видит** историю чата — в промпте должны быть путь к проекту и номер
задачи. Субагент вызывает скилы через `Skill` tool по имени.

### Шаблон промпта для шага analyze

```
Ты работаешь в проекте Galaxy (браузерная игра на TypeScript) по пути
/Users/jangot/Projects/private/galaxy. Правила проекта — в CLAUDE.md, задачи — в
second-brain/tasks/.

Запусти скил `analyze` для задачи номер {NNN}:
1. Вызови Skill tool: skill="analyze", args="{NNN}"
2. Дождись завершения всех действий скила (включая запись `analyze.md`, если стадия
   прошла успешно и не заблокирована открытыми вопросами).

Ты не можешь задавать вопросы пользователю. Если без ответа пользователя анализ
невозможен — запиши вопросы в `## Открытые вопросы` и верни FAILURE с их списком.

В конце ответа дай однострочное резюме: SUCCESS или FAILURE; при FAILURE — одно
предложение с причиной.
```

### Шаблон промпта для шага plan

```
Ты работаешь в проекте Galaxy (браузерная игра на TypeScript) по пути
/Users/jangot/Projects/private/galaxy. Правила проекта — в CLAUDE.md.

Запусти скил `plan-implementation` для задачи номер {NNN}:
1. Убедись, что `analyze.md` существует в папке задачи.
2. Вызови Skill tool: skill="plan-implementation", args="{NNN}"

В конце ответа: SUCCESS или FAILURE; при FAILURE — краткая причина.
```

### Шаблон промпта для шага do

```
Ты работаешь в проекте Galaxy (браузерная игра на TypeScript) по пути
/Users/jangot/Projects/private/galaxy. Правила проекта — в CLAUDE.md.

Запусти скил `do` для задачи номер {NNN}:
1. Вызови Skill tool: skill="do", args="{NNN}"
2. Внеси изменения согласно `plan.md` и правилам скила `do`.

В конце ответа: SUCCESS или FAILURE; при FAILURE — краткая причина (включая ошибки
сборки/тестов/линтера). Отдельно перечисли, что пользователю проверить в браузере.
```

### Шаблон промпта для шага fix-tests

```
Ты работаешь в проекте Galaxy (браузерная игра на TypeScript) по пути
/Users/jangot/Projects/private/galaxy. Правила проекта — в CLAUDE.md.

Запусти скил `fix-tests` для задачи номер {NNN}:
1. Вызови Skill tool: skill="fix-tests", args="{NNN}"
2. Почини упавшие после реализации тесты согласно правилам скила.

В конце ответа: SUCCESS или FAILURE; при FAILURE — краткая причина.
```

## Шаг 1: analyze

Запустить **Agent** с шаблоном «analyze».

После завершения агента — проверить наличие `analyze.md` в папке задачи. Если файла
**нет**:
- если субагент вернул открытые вопросы (анализ заблокирован) → **не** создавать
  `error.md`; показать вопросы пользователю, предложить обсудить, обновить
  `description.md` и перезапустить `chain`; остановиться;
- иначе → **обработка ошибок** (шаг: analyze).

Если `analyze.md` есть, но в нём непустые `## Открытые вопросы`, влияющие на
реализацию — показать их пользователю и спросить, продолжать ли конвейер.

## Шаг 2: plan-implementation

Запустить **Agent** с шаблоном «plan». Нет `plan.md` → **обработка ошибок** (шаг: plan).

## Шаг 3: do

Запустить **Agent** с шаблоном «do».

- Ошибки тестов/линтера → перейти к шагу 4 (fix-tests).
- Неустранимые ошибки сборки или остановка из-за выхода за рамки задачи →
  **обработка ошибок** (шаг: do).

## Шаг 4: fix-tests

Запустить **Agent** с шаблоном «fix-tests».

- Тесты по-прежнему падают → **обработка ошибок** (шаг: fix-tests).
- Иначе → конвейер завершён; сообщить пользователю сводку по всем шагам, что
  проверить в браузере, и предложить `/commit {NNN}`.

## Обработка ошибок

При провале на любом шаге:

1. Создать `{путь к папке задачи}/error.md`:

```markdown
# Ошибка выполнения конвейера

**Шаг:** {analyze | plan | do | fix-tests}
**Дата:** {текущая дата}

## Описание ошибки

{Подробное описание что пошло не так — из ответа субагента или контекста}

## Статус шагов

- {✅ | ❌ | ⏭} analyze
- {✅ | ❌ | ⏭} plan
- {✅ | ❌ | ⏭} do
- {✅ | ❌ | ⏭} fix-tests

(✅ — выполнен, ❌ — упал, ⏭ — не запускался)
```

2. Сообщить пользователю: какой шаг упал, краткая причина, путь к `error.md`.
3. Остановиться. Последующие шаги не запускать.

## Заметки

- Номер задачи обязателен — без него не запускать.
- Шаги строго последовательны: analyze → plan → do → fix-tests.
- Каждый шаг — отдельный **Agent**; связь между шагами — через файлы задачи и код.
- `chain` сам задачу не реализует — только оркеструет.

## Если Agent tool недоступен

Запустить скилы **в одном чате** последовательно через `Skill` tool: `analyze` →
`plan-implementation` → `do` → `fix-tests` (запасной вариант, контекст не изолирован).
