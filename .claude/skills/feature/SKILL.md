# Загрузить контекст фичи

Цель: найти фичу в реестре `second-brain/features/` и подгрузить в контекст всё, что о
ней уже зафиксировано — статус, точки входа, задачи, ссылки, — чтобы пользователю не
пришлось объяснять заново.

## Аргументы

- `$ARGUMENTS`: имя или номер фичи. Обязателен. Может быть номером (`1`, `001`),
  kebab-case (`enemy-formation`), названием на русском («строй врагов») или частью.

## Порядок работы

1. Прочитать `second-brain/features/README.md` — таблица всех фич (№ / Фича / Статус / Запись).
2. Сопоставить `$ARGUMENTS` со строкой таблицы:
   - число → колонка `№` (с учётом ведущих нулей);
   - иначе — нестрогое сравнение по названию и имени файла/папки;
   - одно совпадение → открыть; несколько → показать кандидатов и спросить;
   - нет совпадений → сообщить, показать список, уточнить — опечатка или нужно завести
     новую запись (заводить сразу, не по завершении).
3. Открыть запись:
   - файл `<name>.md` — целиком;
   - папка `<name>/` — `README.md` и `status.md` (если есть). Остальное — только по
     ссылкам, если понадобится.
4. Подтянуть связанный раздел `second-brain/game-design.md` и короткие ADR, если
   запись на них ссылается. Длинные цепочки не разворачивать.
5. Краткое резюме (3–6 предложений): что за фича, статус, что сделано (задачи в
   `tasks-done/`), что дальше.

## Важно

- Только **загрузка** контекста. Хочет начать работу — предложить `/new-task`, не
  запускать самому.
- Фичи нет в реестре, а разговор явно про неё — предложить завести запись по
  конвенции из `features/README.md`.
