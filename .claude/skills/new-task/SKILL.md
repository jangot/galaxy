# Создать новую задачу из контекста чата

Цель: зафиксировать результат обсуждения задачи в чате, создать папку задачи и файл
`description.md` для дальнейшей работы на стадии `/analyze`.

## Аргументы
- `$ARGUMENTS` (опционально): короткое описание. Если не передано — определяется из
  контекста обсуждения.

## Размер задачи: одна задача = одна законченная единица

Проект — один репозиторий, но задача должна быть **одной законченной и проверяемой
единицей** (напр. «корабль игрока: движение и выстрел», «строй врагов», «HUD»). Если
обсуждение охватывает несколько независимых кусков — НЕ склеивать в одну задачу:
предложить пользователю разбивку на несколько задач с зависимостями между ними и
создавать только после подтверждения. Зависимости фиксировать в `description.md`
(напр. «зависит от 004-player-ship»).

## Расположение и именование задач

- Активные задачи: `second-brain/tasks/tasks/`
- Завершённые: `second-brain/tasks/tasks-done/`
- Формат папки: `{NNN}-{описание}` — напр. `004-player-ship`
  - `NNN` — три цифры с ведущими нулями, сквозная нумерация
  - `описание` — kebab-case, на английском (только имя папки)

**Определение номера:** `ls second-brain/tasks/tasks/ second-brain/tasks/tasks-done/`,
взять максимальный числовой префикс среди всех папок и прибавить 1. Если папок нет —
начать с `001`.

**Если папка с таким номером уже существует** — предупредить, спросить: перезаписать
`description.md` или отменить.

## Структура выходного файла

Результат: `second-brain/tasks/tasks/{NNN}-{описание}/description.md`

Файл **на русском**, содержит:

```markdown
# Задача: {название}

## Суть задачи
{Кратко что нужно сделать — 3-5 предложений по итогам обсуждения}

## Детали и требования
{Конкретные требования: механика, управление, числа (скорости, размеры, очки),
визуал — всё, что проговорено}

## Критерии готовности
{Как понять, что задача сделана: что видно на экране / что проверяют тесты}

## Контекст
{Фича и её дизайн (`second-brain/features/{NNN}-{name}/design.md`, какой пункт
нарезки), связанные модули, разделы game-design.md}

## Зависимости
{Ссылки на связанные задачи; иначе «нет»}

## Открытые вопросы
{Нерешённые вопросы — если есть}
```

## Порядок работы

1. Проанализировать контекст чата — что обсуждалось, какая задача складывалась. Если
   задача — пункт нарезки из `design.md` фичи (после `/design-feature`), брать суть и
   границы оттуда; после создания добавить задачу в раздел «Задачи» README фичи.
   Если фича крупная и ещё не проектировалась — предложить сначала `/design-feature`.
2. Проверить размер задачи (см. выше; при необходимости — предложить разбивку).
3. Определить номер и описание папки.
4. Создать папку задачи и `description.md` с зафиксированными деталями.
5. Если в обсуждении приняты решения по геймдизайну — предложить обновить
   `second-brain/game-design.md` (не менять молча).
6. Сообщить пользователю: путь к задаче, краткое резюме, следующий шаг: `/analyze {NNN}`
   или `/chain {NNN}`.

## Заметки
- new-task — нулевая стадия конвейера (new-task → analyze → plan-implementation → do → fix-tests).
- Не запускать analyze автоматически — только предложить.
- Фиксировать только то, что реально проговорено; не выдумывать. Недостающее — в «Открытые вопросы».
